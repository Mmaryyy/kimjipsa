# 개발용 테스트 데이터 (P4.5)

`yarn dev` 실행 후 화면 구석의 **목업 모드** 스위치로 켜고 끈다.
Supabase URL·키·로그인이 없어도 스위치를 사용할 수 있다.
기본은 꺼짐이며 `kimjipsa-mock-enabled=1` 쿠키로 상태를 저장한다.
전환할 때 페이지를 새로 불러오며 환경 변수 설정이나 서버 재시작은 필요 없다.
끄면 기존 Supabase 경로로 돌아간다.

`NODE_ENV=development`일 때만 활성화된다. 프로덕션 번들에는 스위치 코드가
포함되지 않으며, 프로덕션·테스트 환경의 서버는 쿠키가 있어도 무시한다.
서버는 요청 쿠키를, 브라우저는 문서 쿠키를 읽는다.
서버·브라우저 Supabase 생성 함수도 목업 모드에서 실제 연결을 거부한다.

## 사용법

- 기본 진입은 지수 시점이며 홈, 일정 월·주·일, 가정·구성원, 설정에 데이터가 나온다.
- 화면 위의 **테스트 데이터** 안내에 현재 표시 이름이 나온다.
  **나 · 지수**, **배우자 · 민호**로 시점을 바꾼다.
  가정은 **도토리네**이며 양쪽 모두 관리자다.
- **로그인 화면**, **가입 · 약관**, **가입 · 가정**으로 기존 가입 화면을 연다.
  목업 로그인 버튼은 외부 OAuth 대신 약관 단계로 이동한다.
  약관·프로필 저장 → 가정 생성 → 가정 화면까지 메모리에서 진행한다.
- 저장·삭제·카테고리 순서·홈 설정·축하 카드 닫음·초대는 서버 메모리에만 반영한다.
  화면 이동·새로고침·시점 및 가입 단계 전환 후에도 유지된다.
  브라우저별 세션 쿠키로 메모리를 구분하며 같은 브라우저의 탭은 쿠키를 공유한다.
  개발 서버 재시작·1시간 무활동 후에도 초기화된다. 파일·DB에는 쓰지 않는다.
- 지수의 개인 일정 **건강검진**은 민호 시점에서 시간 슬롯만 보인다.
  응답에도 제목·장소·메모가 없고 상세 조회는 `null`, 수정·삭제는 거부된다.
  공유 일정을 개인으로 바꾸는 행동도 작성자만 가능하다.
- 초대 안내는 `/invite/10000000-0000-4000-8000-000000000200`(사용 가능),
  끝자리 `201`(사용됨), `202`(만료됨)로 확인한다.
  가입·가정 단계에서 클라이언트 링크로 사용 가능 초대에 이동하면 수락할 수 있다.
  새로 만든 초대는 현재 메모리 세션 안에서만 유효하므로 외부 공유용으로 쓰지 않는다.

## JSON 구성과 다음 Phase 추가 방법

| 파일                    | 내용                                                  |
| ----------------------- | ----------------------------------------------------- |
| `family.json`           | 가정과 두 구성원, 역할, 사용자 식별자                 |
| `events.json`           | 프로토타입 공유·개인·종일·시작 시각만·D-day·축하 주년 |
| `event-categories.json` | 도토리네·회사·병원·약속·가족·기타와 표시 순서         |
| `home-settings.json`    | 기본 월 뷰, 다가오는 일정 켜짐, 5개 표시              |
| `invites.json`          | 사용 가능·사용됨·만료 초대, 현재 시각 기준 만료 일수  |

가정·이름·일정 제목·시각·장소·메모는 `prototype/home.html`, `calendar.html`의
2026년 10월 14일 기준 샘플과 맞췄다. 프로토타입에서 숨긴 민호 개인 일정의
원본 제목은 **민호 개인 일정**으로 두고 응답에서 기존 권한 필터로 숨긴다.
샘플 날짜는 JSON에 기준 날짜로 기록하고, 화면에 오늘 일정이 계속 나오도록
기존 방식대로 10월 14일과의 날짜 차이를 실행일에 적용한다.
결혼기념일은 기준일 3일 전을 원년으로 두어 다음 주년이 D-362, 1주년이 된다.
별도의 **처음 만난 날**은 오늘이 1주년인 축하 일정으로, 홈 축하 카드와 닫기를 확인할 수 있다.

일정의 `mock_start_offset`, `mock_end_offset`은 서울 기준 오늘부터의 날짜 차이다.
`mock_years_ago`는 주년의 기준 연도를 과거로 옮긴다. 이 보조 필드는 shared 서버 목업 모듈에서
검증·변환 후 제거한다. 보조 필드를 빼면 `start_date`, `end_date`를 그대로 쓴다.
D-day 남은 일수·주년 수는 기존 계산 함수를 쓰며 JSON에 결과를 저장하지 않는다.

새 Phase는 해당 영역 JSON을 이 폴더에 추가하고 파일 모양의 스키마와 초기 변환을
`src/shared/server/mock-data.schema.ts`의 `mockDataSchemas`에 등록한다.
해당 `entities/<영역>/api/server.ts`에서만 `mockContext()` 확인 후 `mockJson(파일명)`으로 읽는다.
파일명은 등록된 이름만 서버 코드 상수로 전달하고 요청 입력을 파일명으로 사용하지 않는다.
같은 파일명은 항상 등록된 단일 스키마로 검증하고 세션 메모리를 공유한다.
첫 동시 요청도 진행 중인 읽기를 공유하므로 파일 읽기와 초기 변환은 한 번만 수행한다.
권한 필터는 실제 조회와 동일하게 통과시키고 저장·삭제도 entity 서버 분기에서만
메모리를 바꾼다. 클라이언트에 원본 JSON을 import하거나 별도 목업 fetch를 만들지 않는다.
원본 JSON은 개인 일정 내용을 포함하므로 `public/`에 두지 않는다.
실제 연결이 필요한 인증·Realtime 같은 경로에는 개발 전용 우회를 추가한다.

## 프로토타입 요소 대조 범위

P4.5는 새 서비스 화면을 만들지 않고 기존 P1~P4 화면에 데이터를 공급한다.
다음 표는 `docs/design/prototype/`의 요소와 데이터 연결 지점을 대조한 것이다.

| 프로토타입 요소                                                                                          | 기존 구현과 목업 연결                                             |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `ob-step-login`, `ob-step-terms`, `ob-step-home`, `ob-step-invite`                                       | 로그인·프로필·가정 단계 선택, 가정 화면의 초대 생성               |
| `today-schedule`, `upcoming-widget`, `dday-section`                                                      | 오늘 일정, 일주일 내 일정, 민호 생일·결혼기념일 D-day             |
| `cal-grid`, `cal-day-list`, `view-month/week/day`                                                        | 기존 월·주·일 렌더러에 같은 일정 응답 공급                        |
| `sheet-new-event`, `sheet-event-detail`, `f-title/place/allday/start/end/category/private/memo`          | 기존 등록·상세·수정·삭제 화면, 개인 일정 필터 유지                |
| `set-profile`, `set-members`, `set-invite`, `set-home`, `s-cal-categories`, `set-appearance`, `s-logout` | 표시 이름·두 구성원·초대·홈 설정·카테고리·화면 모드·목업 로그아웃 |

프로토타입과 기존 화면의 배치·진입 방식 차이(r023)는 합의대로 P4.6에서 다룬다.
`stock-summary`, `cart-summary`, `f-remind`, `set-notify`, 재고 메타데이터,
`set-ai`, `set-memory`, 탈퇴는 이후 Phase 범위이며 이번에 추가하지 않는다.
브라우저에서 실제 시안과의 시각 대조는 별도 확인이 필요하다.
