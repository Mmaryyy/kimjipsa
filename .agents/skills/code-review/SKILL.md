# code-review

> 이름이 Claude Code 내장 `/code-review`와 겹친다. 프로젝트 전용 기준(요구사항 ID, FSD, 프라이버시)으로 리뷰하려면 이 스킬의 기준을 함께 적용한다.

**사용자 승인 없이 실행하지 않는다.** 리뷰는 읽기만 하고, 수정은 사용자가 요청할 때만 한다.

## 절차

1. 대상 확인: `git diff`/지정된 파일. 관련 요구사항 ID를 `docs/01-project/REQUIREMENTS.md`에서 찾는다.
2. 아래 항목을 대조한다. 문서에 없는 기준을 만들어 지적하지 않는다.

| 항목 | 기준 |
| --- | --- |
| 요구사항 충족 | ID의 동작, 범위(MVP/M3), `SCN-*` 시나리오. 요구사항에 없는 기능 추가 여부 |
| 프라이버시 | 개인 일정 제목·장소·메모가 화면·API·Realtime·챗봇으로 배우자에게 나가는 경로가 있는가 (CAL-04, BOT-10) |
| 권한·인증 | 클라이언트가 보낸 id 신뢰, 관리자 전용 동작, 가정 격리(RLS) |
| 비밀 정보 | AI 키 평문 노출, 로그, 클라이언트 번들 |
| 아키텍처 | FSD import 방향, 같은 레이어 슬라이스 import, 깊은 경로 import, 서버 전용 코드 위치 |
| 변경 경로 | 직접 요청은 즉시 실행, 챗봇 판단은 pending + 5분 만료 |
| 타입 안정성 | `any`, 도메인 키/라벨 단일 원천, `satisfies`, `import type` |
| 코드 중복 | 기존 컴포넌트 재사용, 복사된 JSX/로직 |
| 파생 상태 | 저장하지 말아야 할 파생 값 저장 |
| 성능 | 불필요한 재조회·구독, 큰 서드파티를 `index.ts`에서 재수출 |
| 접근성 | 텍스트 라벨, 포커스, 동작 줄이기 |
| 예외 처리 | 빈/오류/로딩, AI 키 없음·오류·한도, 연결 끊김 |
| 테스트 | 요구사항 ID와 연결된 테스트 누락 |
| 불필요한 복잡성 | 과한 추상화, 미사용 의존성 |
| 문서 일치 | 문서/명세와 구현이 어긋나면 임의 판단 말고 보고 |

3. 문제마다 **심각도**(Critical: 유출·권한·데이터 손상 / High: 요구사항 불충족 / Medium / Low), 위치(`파일:줄`), 이유, 수정 방향을 적는다.
4. 확신이 낮은 항목은 추측이라고 표시한다. 문제가 없으면 없다고 말한다.
5. 보고 형식: 심각도 순 목록 → 요약 한 단락. 고치는 작업은 하지 않는다.
