# write-tests

## 절차

1. **요구사항 확인**: 대상 ID와 연결된 `SCN-*`를 `docs/01-project/REQUIREMENTS.md`, `docs/기능명세.html`에서 찾는다.
2. **전략 확인**: `docs/03-guidelines/TESTING.md`. 도구는 Vitest + Testing Library + Playwright다(ADR-0006). 그 밖의 테스트 도구는 승인 없이 설치하지 않는다.
3. **대상 분석**: 순수 규칙(단위) / 상태별 UI(컴포넌트) / 서버 라우트·권한(통합) / 두 사용자 흐름(E2E) 중 어디서 검증할지 정한다. 개인정보·변경 경로·데이터 정합을 우선한다.
4. **정상 시나리오 정의**: 명세의 확인 시나리오를 그대로 테스트 케이스로 옮긴다. 이름에 요구사항 ID와 시나리오 ID를 넣는다.
5. **예외 시나리오 정의**: 권한 없음, AI 키 없음/오류, 만료, 중복, 빈 값(수량 0은 유효), 연결 끊김, 경계 날짜.
6. **테스트 구현**: 구현 세부가 아닌 사용자 관찰 가능한 동작을 단정한다. 외부 서비스(AI, 구글, 푸시)는 어댑터 경계에서 대체한다. 실제 키·개인정보를 쓰지 않는다. 개인 일정 마스킹은 화면이 아니라 **응답 데이터**를 검사한다.
7. **테스트 실행**: **사용자 승인을 받은 뒤에만** 실행한다. 승인 전에는 "작성만 했고 실행하지 않았다"고 보고한다.
8. **결과 보고**: 추가한 테스트와 연결 ID, 실행 결과(실행했다면 실패 출력 포함), 비어 있는 시나리오. 기존 실패는 변경 파일 결과와 구분한다.
9. 코드 작업을 마치면 `yarn format` → `yarn format:check`(`package.json`이 없으면 건너뛰고 보고).
