# 프로젝트 개요

상태 표기: **CONFIRMED**(기획서·명세·사용자 승인으로 확정), **PROPOSED**(AI 제안), **PENDING**(결정 필요). 별도 표기가 없으면 기획서 v0.11에서 가져온 CONFIRMED 내용이다.

## 한 줄 정의

신혼부부가 일정, 재고, 장바구니를 한곳에서 같이 관리하고, 그 데이터를 아는 AI 집사 챗봇이 조회와 실행, 제안까지 해 주는 가정 관리 서비스. `kimjipsa`는 저장소·패키지에 쓰는 개발용 코드명이다. (기획서 §01)

## 해결하려는 문제 (기획서 §02)

- 장 볼 목록을 공유하고 정리하기 불편하다. 메모앱과 카톡에 흩어져 있다.
- 이미 있는 걸 또 사거나, 떨어진 걸 모른다.
- 일정, 재고, 장보기가 여러 앱에 나뉘어 있다.

| 영역 | ID 접두사 | 한 줄 요약 |
| --- | --- | --- |
| 가정·계정 | `ACC` | 카카오·구글 로그인, 가정 생성, 초대 링크 합류, AI 키·알림·홈 설정, 탈퇴, PWA |

후순위: 재정 관리, 청소·집안일 스케줄. (기획서 §05)

## 제품 설계 원칙 (기획서 §04, §06)

1. **모바일 우선 PWA.** 홈 화면에 설치해 앱처럼 쓰고, 웹 푸시도 PWA 기반이다.
2. **공유가 기본, 비공개는 선택.** 개인 일정의 제목·장소·메모는 화면과 챗봇 어디에서도 배우자에게 나가지 않는다. 숨김은 서버가 요청자 권한으로 거른 데이터만 내려보내는 방식으로 보장한다.
3. **AI는 읽기는 자유롭게, 변경은 두 갈래.** 사용자가 직접 요청한 변경은 바로 실행하고, 챗봇이 스스로 판단한 변경만 채팅 안의 확인 버튼(5분 만료)을 거친다.
4. **BYOK.** 무료 서비스이고 AI 비용은 가정이 부담한다. 관리자가 Claude 또는 Gemini 키를 하나 등록하면 가정 전체가 공유하며, 키는 서버에서 암호화해 저장한다. 키가 없으면 AI 기능만 꺼지고 나머지는 정상 동작한다.
5. **입력 부담 최소화.** 재고 데이터가 죽지 않도록 "다 썼어요", 챗봇 입력, 구매 완료 자동 반영을 둔다.
6. **챗봇 이름은 사용자가 정하고 "김" + 이름으로 표시한다.** (예: "데비" → "김데비")

## 운영 방식

- 서비스 운영 환경: Next.js(PWA) + Supabase + Vercel. (CONFIRMED, `AGENTS.md`. 근거는 기획서 §09)
- 혼자 개발하는 8주, 세 마일스톤(M1~M3). 상세는 `docs/04-planning/ROADMAP.md`.
- 성공 지표(제안): 4주 연속 매주 사용 / 장보기 목록을 메모·카톡 대신 이 서비스로 관리 / 재고 중복 구매 체감 감소. (기획서 §10, "제안" 상태)

## 핵심 사용자 시나리오 (기획서 §07)

1. **온보딩(약 3분)**: 로그인 → 우리 집 만들기 → 카톡으로 초대 링크 공유 → 배우자 수락
2. **홈 "오늘"**: 오늘 일정, D-day, 임박 재고, 장바구니 요약, 우하단 집사 아이콘
3. **일정 등록**: 기본 "둘 다" → 개인 스위치 → 상대에게 반영
4. **장보기 루프**: 소진("다 썼어요") → 장바구니 → 장보기(공동 체크) → 구매 완료 → 재고 반영 확인
5. **챗봇**: 자연어 요청 → 의도 해석 → 실행(챗봇이 판단한 변경은 채팅 안에서 확인 후 실행)
