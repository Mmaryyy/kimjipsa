# 디자인 시스템

이 문서는 기획서·명세에서 확인되는 UI/UX 요구를 정리한다. 시각 규칙과 토큰은 디자인 산출물을 따른다.

- **디자인 산출물 (CONFIRMED):** `docs/design/`. 구현 전에 `docs/design/HANDOFF.md`부터 읽는다.
- **토큰 원본 (CONFIRMED):** `docs/design/tokens.css` (Apple 시스템 컬러, 라이트·다크, 상태 variant `success · info · warning · error`, 타이포 variant 12단계, 간격·모양). 색, 폰트, 간격, 라운드는 이 파일의 토큰만 쓰고 임의로 만들지 않는다.
- **앱 토큰 파일 경로:** `src/app/styles/tokens.css`. 원본을 옮긴 파일이며, Tailwind 테마 연결은 `src/app/styles/globals.css`에 둔다.

### 스타일 구현 기준 (CONFIRMED, 사용자 결정 2026-10-19)

- 컴포넌트 전용 스타일은 컴포넌트의 Tailwind 유틸리티로 작성하고, 상태·크기별 표현은 CVA(`*.variants.ts`)로 관리한다.
- 반복되는 표현은 공용 컴포넌트·variant를 재사용한다. 입력은 `Input`, 가입 레이아웃과 워드마크는 `onboardingStyles`·`wordmarkStyles`를 사용한다.
- CSS에는 토큰, base 리셋, 커스텀 애니메이션과 범용 유틸리티만 남긴다. 현재 범용 클래스는 `kj-hit`(터치 영역), `kj-overlay`(배경막), `kj-page-header`(안전 영역)이며, 새 `kj-*`는 추가하지 않는다.
- Tailwind 테마는 색·간격·라운드·타이포·글자 굵기의 앱 토큰을 참조한다. 기존 셸의 파생 치수와 모션·비율도 앱 토큰에 모으고, 디자인 원본의 색·간격 값은 바꾸지 않는다.
- P4.7의 클래스별 사용처와 이동 결과는 [스타일 감사](../design/P4.7_STYLE_AUDIT.md)를 참고한다.

## 1. 디자인 방향 (CONFIRMED, 기획서 §04)

- 모바일 우선 반응형 웹, PWA. 홈 화면에 설치해 앱처럼 쓴다.
- 데스크톱에서도 쓸 수 있어야 하지만 기준 화면은 스마트폰이다. 챗봇 아이콘 최소화 위치가 모바일은 하단 내비게이션 바, 데스크톱은 헤더다(BOT-01).
- 챗봇은 "집사" 컨셉이다. 평소에는 우하단 아이콘만 보이고 입력창은 숨긴다.

## 2. UI/UX 원칙

1. **공유가 기본, 비공개는 선택.** 개인 일정 전환은 스위치 하나로 한다(CAL-03).
2. **되돌릴 수 없는 삭제는 대상 이름이 적힌 확인 화면.** 일정(CAL-12), 재고 품목(INV-14), 탈퇴(ACC-15). 예외: 장바구니 개별 삭제는 확인 없음, 체크 항목 일괄 삭제만 확인(CART-13). 챗봇 직접 요청 삭제는 확인 없음(BOT-07).
3. **챗봇의 확인은 채팅 안에서.** 별도 팝업을 쓰지 않고 확인·취소 버튼을 메시지 안에 둔다. 5분 뒤 버튼을 비활성화한다(BOT-08).
4. **입력 부담을 줄인다.** 자동완성(INV-10), +/- 버튼(INV-15), "다 썼어요"(INV-04), 자주 사는 품목 한 번에 추가(CART-05).
5. **상태는 눈에 띄게.** 부족·없음·임박은 홈에 요약 노출한다(INV-13).
6. **움직임은 줄일 수 있게.** 시스템 "동작 줄이기"를 켠 사용자에게는 말풍선(BOT-02)과 색종이(CAL-16)를 움직이지 않는다.
7. 아이콘만으로 뜻이 불분명한 핵심 행동에는 텍스트 라벨을 함께 둔다. (`CODING_STANDARDS.md` §7)

- **작은 원형 아이콘 버튼:** `Button size="icon-sm"`은 보이는 원 32px·아이콘 16px이며, `kj-hit`로 누름 영역 44px을 유지한다. 장바구니 스와이프와 편집 일괄 처리에서 담기(Plus·gray), 구매 완료(Check·primary), 삭제(Trash2·danger)에 사용한다. 버튼 사이 간격은 `gap-4`로 두어 누름 영역이 겹치지 않게 한다.

## 3. 반응형 기준

- 모바일 우선으로 만들고 데스크톱으로 확장한다. 브레이크포인트는 768px(시트·채팅 패널), 1024px(사이드바 + 두 컬럼)이다 (CONFIRMED, `docs/design/HANDOFF.md` §7).
- 실제 데이터 개수와 콘텐츠 길이에서 확인한다: 1개/여러 개, 긴 이름, 이미지 없음, 빈 목록.
- 여러 항목이 가능한 UI는 처음부터 목록·grid로 설계한다.

### iOS 홈 화면 앱 상단 여백 (CONFIRMED, 사용자 실측 2026-10-19)

- 사용자 iPhone 홈 화면 앱은 `safe-area-inset-top: 0`이며, 상단 패딩 24px 이하에서는 날짜 윗부분이 흐리고 32px부터 흐림이 없었다. 블러 없는 최소 실험값인 `--sp-8`(32px)을 헤더·온보딩의 최소 상단 여백으로 쓴다. 기존 72px 하한은 제거하고 상태 막대 스타일 `default`는 유지한다.
- 적용 조건은 기존과 같은 `@supports (-webkit-touch-callout: none)` 안의 `display-mode: standalone` 또는 `fullscreen`이다. 일반 브라우저의 헤더 `max(var(--sp-5), inset + var(--sp-2))`와 온보딩 `max(var(--sp-3), inset)`는 유지한다.
- 수정 후 실기기의 스크롤 전·중 상단 흐림, 빈 공간 감소, 하단 탭바와 안전 영역은 사용자 재확인이 필요하다.

- **시트 (CONFIRMED, 사용자 결정 2026-10-22, r119-f1):** 모바일 판정은 일정 시트와 같은 `(pointer: coarse)`를 쓴다. 공용 `Sheet`가 이 조건에서 Vaul `Drawer` 래퍼를 사용하며, 알림 목록·약관·계정 설정·카테고리·일정 상세·날짜와 시간 선택을 포함한 모든 하단 시트에 손잡이와 아래로 끌어 닫기를 제공한다. 스크롤이 맨 위일 때 드래그로 닫고 하단 안전 영역을 반영한다. 데스크톱 표시는 기존대로 유지하며 `ConfirmDialog`는 제외한다.
- **시트 닫기 (CONFIRMED, 사용자 결정 2026-10-22, r127-f1):** 닫힘 콜백은 `onOpenChange(false)` 하나로 통일한다(버튼·바깥 누르기·아래로 스와이프·ESC·뒤로 가기). `showCloseButton`은 기본 `false`이며, 켠 곳의 데스크톱 Sheet에만 머리 오른쪽 끝에 같은 크기·색의 X 버튼(접근성 이름 “닫기”)을 표시한다. 모바일 Drawer는 이 값과 관계없이 X 버튼을 표시하지 않으며 끌기·바깥 누르기·뒤로 가기로 닫는다. 제목은 머리 가운데에 두고, 폼의 취소·완료 같은 동작은 닫기 버튼과 구분해 `leadingAction`(왼쪽, 닫힘 콜백 제공)과 `action`(오른쪽) 슬롯으로 둔다. 일정 폼의 취소와 닫힘 요청은 변경 사항 확인을 거친다.
- **일정 폼 입력 (CONFIRMED, 사용자 결정 2026-10-21, P5.5):** 변경 사항이 있으면 취소·ESC·드래그 모두 닫기 확인을 거친다. 날짜·시간 휠은 부모 Drawer 위의 중첩 Drawer로 열고, 휠 조작은 닫기 드래그에서 제외한다. 선택한 쪽에 포커스를 준 뒤 닫을 때 연 행으로 돌려보낸다. 포인터로 연 터치 탭·행에는 포커스 테두리를 숨기고, 키보드 기기의 포커스 표시는 유지한다. 데스크톱 폼은 기존 가운데 Sheet와 직접 입력을 유지한다.

## 4. 주요 화면 패턴

- 빨강(`--sys-red-ic`)은 일요일·공휴일 전용, 카테고리 색으로 쓰지 않는다.

- **페이지 제목 (CONFIRMED, 사용자 결정 2026-10-20):** 페이지 제목은 `title-lg` 하나로 통일한다. `PageHeader`는 제목 크기 변형을 제공하지 않는다.

- **선택 날짜 (CONFIRMED, 사용자 결정 2026-10-20):** 월·주 뷰와 홈 주간 스트립의 선택 원은 `--fill-secondary`(라이트·다크 자동), 숫자는 `font-semibold`와 원래 의미 색(공휴일·일요일 `--sys-red-ic`, 토요일 `--accent-text`, 평일 기본 글자색, 달 밖 `--label-tertiary`)을 유지한다. 요일의 의미 색을 알아보기 쉽도록 프로토타입의 글자색 원과 반전 숫자에서 변경했다.

- **토요일·오늘 (CONFIRMED, 사용자 결정 2026-10-20):** 토요일 숫자·요일 머리·날짜 묶음 제목은 `--accent-text`이며 공휴일의 빨강과 달 밖 회색이 우선한다. 오늘 숫자는 요일 색을 유지하고 `font-bold` + 크기 32px 원의 `1.5px dashed currentColor` 테두리로 표시한다. 선택된 오늘은 `--fill-secondary` 채움도 함께 쓴다. 주·일 제목의 오늘도 요일 색과 굵게를 따른다.

- **월 칸 공휴일 라벨 (CONFIRMED, 사용자 결정 2026-10-20):** 날짜 버튼을 `container-type: inline-size`로 두고 데이터와 무관하게 `--holiday-chars: 6`을 고정한다. 스위트 한글의 실제 폭(약 0.86em)에 여유를 둔 `font-size: clamp(9px, calc(100cqi / var(--holiday-chars) / 0.87), 11px)`로 계산하며 자간은 0을 유지한다. 같은 화면 폭에서는 모든 월의 공휴일 라벨이 동일한 크기(9~11px)를 쓴다. 6글자를 넘는 이름이나 9px로도 부족한 좁은 칸에서만 말줄임하며 날짜의 `aria-label`에는 전체 표시 이름을 유지한다. 칸 안의 이름은 띄어쓰기 없이 표시한다. 표시 이름 표는 `기독탄신일` → `크리스마스`, `전국동시지방선거` → `전국지방선거`, `부처님 오신 날` → `부처님오신날`이다(마지막 항목은 공백 제거). 라이트·다크에 같은 규칙을 쓴다. 월 뷰 요일 머리는 달 밖 날짜·공휴일 여부와 무관하게 일요일 빨강, 토요일 `--accent-text`, 평일 회색이다.

- **절기·잡절 (CONFIRMED, 사용자 결정 2026-10-20, P4.13):** 월 칸은 공휴일과 같은 자리·6글자 기준 크기·말줄임 규칙으로 이름을 표시하되 `--label-secondary` 회색을 쓴다. 기존 `holidayDisplayNames`로 표시 이름을 정하고 원본 이름은 캐시에 보존한다. 날짜 숫자는 절기·잡절로 색을 바꾸지 않으며 기존 주말·달 밖 색을 유지한다. 같은 날 공휴일이 있으면 칸에는 공휴일만, 월 선택일·주·일 목록에는 모두 표시한다. 목록의 절기·잡절은 회색 점과 `청명 · 절기`/`초복 · 잡절`의 정적 줄이다. 날짜 aria-label에는 칸에서 가려진 이름까지 포함한다. 홈 달력 날짜에도 이름을 제공하되 홈 오늘 일정·다가오는 일정·일정 개수·날짜 aria의 `일정 N개`에는 넣지 않는다. 표시 설정 없이 항상 켜 둔다.

- **월 달력 여러 날 일정 (CONFIRMED, 사용자 결정 2026-10-22, P5.6):** 시작일과 종료일이 다른 일정은 제목 없이 높이 8px(`--calendar-bar-height`) 막대로 표시한다. 기존 색점과 같은 카테고리 토큰을 쓰고 불투명도는 라이트·다크 모두 50%로 낮춘다. 개인 일정은 기존 색점과 같은 `--sys-gray3` 회색을 유지한다. 시작일·종료일을 모두 포함하고 일요일 시작의 주마다 구간을 나누며, 실제 시작·종료 끝만 `--r-bar`(2px)로 둥글고 주·화면 경계에서 잘린 끝은 각지게 한다. 시작일순·같은 시작일이면 종료일이 늦은 순·일정 ID순으로 각 주의 빈 줄에 배치한다. 최대 두 줄이며 넘치는 구간은 해당 날짜에 하루 일정과 같은 색점으로 표시하고 다음 주에서 다시 배치한다. 날짜 숫자 → 공휴일·절기 이름 → 하루 일정 색점 → 여러 날 일정 막대 순서로 표시하고, 눈으로 보이는 간격이 같도록 날짜·이름 사이는 `--calendar-date-gap`(`--sp-1` = 4px), 색점·막대 사이와 막대 두 줄 사이는 `--calendar-mark-gap`(4px + 1px, 글자 안쪽 여백 보정)을 쓴다. 이름은 글자 크기 높이(leading-none), 색점은 5px이고, 막대는 두 줄(8px + 간격 + 8px) 자리를 내용이 없어도 확보한다. 첫 줄 막대는 색점 바로 아래에 놓아 막대가 한 줄일 때도 색점과의 간격이 같게 보인다. 하루 일정 색점은 최대 3개 규칙을 유지하며, 날짜의 일정 개수에는 숨긴 구간도 포함한다. 홈의 월 달력도 같은 규칙을 쓰고 홈 주간 스트립·주·일 보기는 유지한다.

- **데스크톱 폭 (CONFIRMED, 사용자 결정 2026-10-20):** 홈을 포함한 모든 페이지의 공통 본문 최대 폭은 1120px이다.

- **홈 구성 저장 (CONFIRMED, 사용자 결정 2026-10-20):** 별도 저장 버튼 없이 조작 즉시 저장한다. 성공하면 짧은 토스트 '홈 구성을 저장했어요'를 표시하고 실패하면 이전 값으로 되돌린 뒤 오류 토스트를 표시한다.

- **달력 헤더 (CONFIRMED, 사용자 결정 2026-10-20):** 첫 줄은 왼쪽 기간 제목(`title-lg`·기본 글자색·h1)과 오른쪽 `TextButton`(sm, 아이콘 없이 "일정 등록", 홈 '오늘 일정'의 '캘린더' 링크와 같은 글자 버튼)으로 구성한다(2026-10-20 사용자가 직접 다듬음, r075). 둘째 줄 왼쪽에는 내용 폭의 작은 월·주·일 전환, 오른쪽에는 이전·오늘·다음을 한 묶음으로 둔다. 오늘은 항상 표시하고 이동 버튼은 보조 글자색·아이콘색을 쓰며 각각 44px 터치 영역과 aria-label을 유지한다. 월 제목은 `yyyy년 M월`, 주 제목과 aria-label은 `yyyy년 M월 N주차`, 일 제목은 기존 날짜·요일을 유지한다. 주는 일요일 시작이며 그 주 목요일이 속한 연월과 `ceil(목요일 날짜 / 7)` 주차를 쓴다. 달력 본문의 공휴일 이름 줄·오늘 점선 원·선택 원·요일 색 규칙은 유지한다.

- 채팅 메시지 버블, 인라인 확인 버튼 그룹

### 날짜·시간 입력 (CONFIRMED, 사용자 결정 2026-10-22)

- 모든 날짜·시간 입력은 `shared/ui/date-time-input`의 `DateTimeInput`을 사용한다. 모바일(`pointer: coarse`)은 휠 시트, 데스크톱은 직접 입력이다.

- 휠·시트와 관련 유틸은 공용 모듈의 공개 진입점으로만 가져오며 `shared/ui` 배럴에는 넣지 않는다.

### 첫 화면 준비와 섹션 스켈레톤 (CONFIRMED, 사용자 결정 2026-10-20, P4.12)

- 로그인 확인 중에는 스플래시만 표시한다. 최소 900ms와 200ms 페이드(동작 줄이기에서는 페이드 대기 없음)를 유지한다.
- 홈(`/`) 진입은 로그인 확인 후 일정·카테고리·홈 설정·D-day 닫음·공휴일 연도·가정 정보를 TanStack Query로 미리 불러온다. 화면 훅과 같은 쿼리 옵션을 사용한다. 모두 끝나거나 최대 3초가 지나면 페이드한다. 실패도 완료로 처리하고 화면의 기존 재시도 UI에 맡긴다. 제한 시간 뒤에도 요청은 계속되어 캐시를 채운다. 다른 경로는 로그인 확인까지만 기다린다.
- 홈 미리 불러오기와 화면 훅의 공용 쿼리 옵션 6종은 `staleTime: 30_000`, `retryOnMount: false`를 사용한다. 첫 마운트에서 같은 데이터를 재요청하거나 실패를 로딩으로 바꾸지 않으며, 사용자가 기존 재시도 버튼으로 다시 요청한다. 일정의 30초 주기 조회와 Realtime 무효화는 유지한다. 공휴일·절기·잡절 쿼리는 예외로 `staleTime: 10_800_000`을 쓰며 서버 캐시도 3시간마다 재검증한다.
- 로딩 상태 안내는 페이지 안에서 하나로 모으고, 섹션 제목은 로딩 중에도 제목 탐색에 남긴다. 로딩 중 날짜 버튼은 일정 개수를 읽지 않는다. 늦게 도착한 홈 기본 보기 설정은 사용자가 이미 선택한 날짜와 보기를 덮어쓰지 않는다.
- 기존 일정 API는 기간 제한 없는 목록 하나로 이번 주·다가오는 일정·D-day를 함께 제공한다. 별도 주간 캐시를 만들지 않는다. 공휴일은 URL의 유효한 `date`(없으면 오늘)를 기준으로 홈 월 보기와 연말 주간 스트립에 필요한 연도를 포함한다.
- 스켈레톤은 실제 레이아웃과 같은 크기·배치로 섹션 단위로 만든다. 달력은 실제 날짜 계산·요일 머리·7칸·행 수·반응형 간격을 그대로 사용하고, 일정 줄은 시간 폭·카테고리 점·본문·보조 문구·D-day 정렬을 따른다. 설정은 구역 제목과 실제 줄 높이를 따른다. 범용 ListSkeleton은 범용 목록에만 쓴다. 동작 줄이기에서는 점멸하지 않는다.
- 축하 카드는 일정과 닫음 상태가 확인되기 전에는 자리를 비운다. 표시할 카드가 확인된 경우에만 실제 카드를 넣는다. 표시 여부를 모르는 상태에서 모든 사용자에게 빈 카드 높이를 남기지 않는다.
- 허용 예외(A안, 사용자 결정 2026-10-20): 미리 불러오기 최대 3초를 넘긴 느린 경우에만 실제 일정 수와 스켈레톤 3줄의 차이, 데이터 도착 후 맨 위에 삽입되는 축하 카드에 따른 작은 레이아웃 이동을 허용하며, 고정 높이·내부 스크롤·섹션 숨김은 적용하지 않는다.
- 구현 한계(미해결): 응답 전에는 실제 일정 수·날짜 그룹·구성원 수·줄바꿈을 알 수 없다. 첫 로딩의 일정은 3줄, 다가오는 일정은 설정 개수(설정 전 5개), D-day는 3줄, 구성원은 2명 모양을 사용한다. 이 예상 개수와 실제 개수 차이, 설정 전후의 홈 보기 차이, 축하 카드 삽입에 의한 높이 변화는 남을 수 있다. 캐시가 있으면 재조회 중에도 기존 콘텐츠를 유지한다.

## P10.6 탐색 유리 재질과 하단 렌즈

차용 출처: `docs/design/reference/liquid-glass/DESIGN.md`의 유리 재질·하단 탭 모션·대체 모드와 `tokens.css`, `motion-tokens.ts`.
원본의 색 체계·글꼴·본문 구조는 가져오지 않는다. 기존 파란 primary와 lg 이상 사이드 메뉴를 유지한다. 홈 알림 아이콘은 같은 유리 재질의 44px 원형 버튼으로 표시하고 안 읽음 점의 파란색은 유지한다.

- 하단 탭은 콘텐츠 위의 캡슐이다. 머리 오른쪽 등록·편집·설정은 각각 글자 캡슐 `Button variant="glass"`다. 높이와 최소 높이는 `var(--hit)`(44px), 좌우 여백은 `px-4`, 글자 크기는 `text-[length:var(--type-label-size)]`(15px), 굵기는 `font-semibold`다. 일정·장바구니 설정은 카테고리 관리, 재고 설정은 목록 관리 시트를 연다. 아래쪽 관리하기 버튼은 두지 않는다.
- 유리는 탐색 컨트롤에만 쓴다. 그룹은 backdrop 하나만 사용하고 머리 전체를 불투명하게 덮지 않는다. 정지 선택은 회색 면과 inset 그림자만, 아이콘은 선택 여부와 렌즈 복사본 모두 같은 Lucide 선형을 쓰고 색만 바뀐다.
- 머리 유리 글자 버튼은 하단 탭 비선택 글자와 같은 `text-muted-foreground`다. 홈 종 아이콘도 `text-muted-foreground`를 쓴다. 하단 탭의 비선택 아이콘은 `--icon-secondary`이며, 선택 탭과 렌즈 안 복사본의 글자·아이콘은 `text-primary`다. 마스크에도 쓰는 `--glass-text` 토큰 값은 유지한다.
- 앱 토큰 `--glass-bg`, `--glass-bg-hover`, `--glass-bg-pressed`, `--glass-bg-opaque`, `--glass-text`, `--glass-border`, `--glass-filter`, `--glass-sheen`, `--glass-edge`, `--glass-highlight`, `--glass-optics-opacity`, `--glass-selected-bg/shadow/text/opaque`, `--tab-lens-bg/shadow/edge`, `--shadow-glass`는 `src/app/styles/tokens.css`에 둔다. 라이트는 흰색 50%, 다크는 차콜 64%, 필터는 둘 다 blur 10px·saturate 1.65다. 다크 가장자리·그림자는 별도 값이다.

### 재고 수량 스테퍼 (CONFIRMED, 사용자 결정 2026-11-02, 시안 E)

- 재고 목록의 수량 모드만 기본으로 접는다. 높이 30px의 회색(`--fill-secondary`) 알약 안에 숫자(15px semibold)와 단위(13px muted)를 공백 없이 `1팩`처럼 표시하며 누름 영역은 44px이다.
