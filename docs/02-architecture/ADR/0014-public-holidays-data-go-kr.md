# 0014. 공휴일·절기·잡절 데이터: 공공데이터포털 특일정보 API

- 결정 ID: ADR-0014 (관련 DEC: DEC-015, CAL-17)
- 결정 날짜: 2026-10-20
- 상태: Accepted

## 배경
일정 캘린더에 한국 공휴일을 표시한다(CAL-17, 2026-10-20 사용자 요청). 대체공휴일·임시공휴일은 해마다 정해지므로 공식 출처에서 받아야 한다. 사용자가 권장안 A를 승인했다(2026-10-20).

## 검토한 대안
- B. 공휴일 목록 내장: 키가 필요 없지만 임시공휴일은 코드 수정·배포가 필요하다.
- C. 구글 한국 공휴일 캘린더: API 키가 필요하고 공식 출처가 아니다.

## 최종 결정
- 한국천문연구원 특일정보 API의 공휴일 정보(`getRestDeInfo`, `solYear` 단위, JSON)를 서버 라우트에서만 호출한다. 서비스 키는 서버 전용 환경 변수 `DATA_GO_KR_SERVICE_KEY`에 둔다.
- `isHoliday`가 `Y`인 날만 쓴다(날짜·이름).
- 외부 응답 원문은 캐시하지 않고, 검증을 통과한 공휴일 목록만 연도 키로 서버 데이터 캐시에 넣는다(3시간마다 재검증). 갱신에 실패하면 이전 성공 값을 그대로 쓴다. 실패 직후에는 같은 서버 프로세스에서 해당 연도의 외부 호출을 5분 동안 쉰다. 원문 fetch는 `cache: "no-store"`, 검증된 목록은 `unstable_cache`로 10800초 재검증하며 서비스 키는 캐시 키에 넣지 않는다. 클라이언트 `staleTime`도 3시간이다. DB 테이블은 만들지 않는다(2026-10-20 사용자 결정, r064-f1).
- 키가 없거나 외부 API가 실패하면 이전 성공 값을 유지하며, 성공 캐시가 비었을 때만 서버 로그와 함께 빈 목록을 돌려주고 캘린더는 공휴일 없이 정상 동작한다. 오류 화면을 띄우지 않는다.
- 목업 데이터 모드(P4.5)에서는 `mocks/`의 공휴일 JSON을 쓴다.

- 표시 이름 바꿈 표는 `entities/holiday` 한 곳에 두고 `기독탄신일` → `크리스마스`, `전국동시지방선거` → `전국지방선거`, `부처님 오신 날` → `부처님오신날`로 표시한다. 마지막 항목은 6글자 기준에 맞춰 공백만 제거한다. API·목업 원본과 서버·클라이언트 캐시 이름은 유지한다(2026-10-20 사용자 결정).

## 결정 이유
공식 출처라 대체·임시공휴일이 반영되고, 캐시로 호출 수가 적어 무료 한도 안에 든다. 테이블이 없어 마이그레이션이 필요 없다.

## 예상 영향
- 공공데이터포털 활용 신청과 서비스 키 발급이 필요하다(사용자 할 일). 키는 `.env.local`과 Vercel 환경 변수에 넣는다.
- 챗봇의 공휴일 답변은 이 결정의 범위가 아니다.

## 데이터 범위 확장 (P4.13, 사용자 결정 2026-10-20)

- CAL-17을 24절기(`get24DivisionsInfo`)·잡절(`getSundryDayInfo`)까지 확장한다. 공휴일과 같은 서비스 키로 연도 단위 조회하고, 같은 Zod 날짜·이름·완전성 검증을 거친다. 절기·잡절은 `isHoliday: N`도 포함하며, 이 필드가 없어도 날짜·이름 검증을 통과하면 표시한다. 공휴일은 `isHoliday` 필수 검증을 유지한다.
- 검증된 목록만 `unstable_cache`로 10800초 캐시한다. 캐시 키는 공휴일 `holidays`, 절기 `solar-terms`, 잡절 `sundry-days`로 분리하고 각각 연도를 포함한다. 실패 시 이전 성공 값을 유지하고 성공 값이 없으면 빈 목록을 반환한다. 5분 백오프도 종류·연도별로 독립적이다. DB 테이블과 환경 변수는 추가하지 않는다.
- 기존 `GET /api/holidays?year=`가 세 종류를 함께 반환한다. 각 항목은 `date`, `name`, `kind: holiday | solarTerm | sundry`다. 인증·연도 검증·성공 응답 형식은 기존과 같다. 한 종류가 실패해도 나머지는 반환한다.
- 클라이언트는 기존 `holidaysQueryOptions`의 `["holidays", year]`와 `staleTime: 10800000`을 그대로 쓴다. 홈 미리 불러오기와 화면 훅이 같은 세 종류의 응답 캐시를 공유해 추가 요청을 만들지 않는다. 표시 이름 변환은 기존 `holidayDisplayNames`를 함께 쓰고 원본 캐시는 보존한다.
- 목업은 `mocks/special-days.json`의 2026~2027년 목록을 사용한다. 절기·잡절은 항상 표시하며 설정 옵션은 이번 범위에 없다.
- 월 칸에서는 기존 공휴일 라벨 자리와 6글자 크기 규칙으로 회색(`--label-secondary`) 이름을 표시한다. 공휴일이 겹치면 칸에는 공휴일만 표시하고 목록에는 둘 다 표시한다. 날짜 숫자색은 절기·잡절 때문에 바꾸지 않는다. 날짜 접근성 이름에는 가려진 이름도 포함한다.
- 월 선택일·주·일 목록에는 회색 점과 `청명 · 절기`/`초복 · 잡절`의 정적 행으로 표시한다. 홈 오늘 일정·다가오는 일정 위젯·일정 개수·날짜의 `일정 N개`에는 포함하지 않는다.
