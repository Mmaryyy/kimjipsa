# 0014. 공휴일 데이터: 공공데이터포털 특일정보 API

- 결정 ID: ADR-0014 (관련 DEC: DEC-015, CAL-17)
- 결정 날짜: 2026-10-20
- 상태: Accepted

## 배경
일정 캘린더에 한국 공휴일을 표시한다(CAL-17, 2026-10-20 사용자 요청). 대체공휴일·임시공휴일은 해마다 정해지므로 공식 출처에서 받아야 한다. 사용자가 권장안 A를 승인했다(2026-10-20).

## 검토한 대안
- B. 공휴일 목록 내장: 키가 필요 없지만 임시공휴일은 코드 수정·배포가 필요하다.
- C. 구글 한국 공휴일 캘린더: API 키가 필요하고 공식 출처가 아니다.

## 최종 결정
- 한국천문연구원 특일정보 API의 공휴일 정보(`getRestDeInfo`, `solYear` 단위, JSON)를 서버 라우트에서만 호출한다. 서비스 키는 서버 전용 환경 변수 `DATA_GO_KR_SERVICE_KEY`에 둔다.
- `isHoliday`가 `Y`인 날만 쓴다(날짜·이름).
- 외부 응답 원문은 캐시하지 않고, 검증을 통과한 공휴일 목록만 연도 키로 서버 데이터 캐시에 넣는다(3시간마다 재검증). 갱신에 실패하면 이전 성공 값을 그대로 쓴다. 실패 직후에는 같은 서버 프로세스에서 해당 연도의 외부 호출을 5분 동안 쉰다. 원문 fetch는 `cache: "no-store"`, 검증된 목록은 `unstable_cache`로 10800초 재검증하며 서비스 키는 캐시 키에 넣지 않는다. 클라이언트 `staleTime`도 3시간이다. DB 테이블은 만들지 않는다(2026-10-20 사용자 결정, r064-f1).
- 키가 없거나 외부 API가 실패하면 이전 성공 값을 유지하며, 성공 캐시가 비었을 때만 서버 로그와 함께 빈 목록을 돌려주고 캘린더는 공휴일 없이 정상 동작한다. 오류 화면을 띄우지 않는다.
- 목업 데이터 모드(P4.5)에서는 `mocks/`의 공휴일 JSON을 쓴다.

## 결정 이유
공식 출처라 대체·임시공휴일이 반영되고, 캐시로 호출 수가 적어 무료 한도 안에 든다. 테이블이 없어 마이그레이션이 필요 없다.

## 예상 영향
- 공공데이터포털 활용 신청과 서비스 키 발급이 필요하다(사용자 할 일). 키는 `.env.local`과 Vercel 환경 변수에 넣는다.
- 챗봇의 공휴일 답변은 이 결정의 범위가 아니다.
