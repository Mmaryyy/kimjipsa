# 0017. 가족 공용 집사와 맥미니 실행 워커

Status: CONFIRMED (2026-11-04 사용자 구현 요청·정책 승인, 맥미니 모델 자동 사용 및 김집사 프로필 추가 지시 반영)

## 결정

- 가족 공용 채팅·기억, 재고 조회·명시적 수량 추가, 영수증 확인을 1차 범위로 구현한다. 기존 BOT-11/12의 개인별 정책을 대체한다. 일정 도구는 후속 범위이며 개인 일정은 이번 워커에 전달하지 않는다.
- Vercel은 사용자 인증·가정 권한·집사 이름·기억 설정을 담당한다. 앱에서 제공자·모델·API 키를 선택하거나 등록하지 않는다. `/api/agent/config`는 워커에게 자기 가정의 설정과 버전만 공급한다. 모델 인증은 맥미니 Hermes가 관리하며 앱·Supabase에 공급하지 않는다. 기존 ACC-08/09·BOT-05/16의 BYOK 정책은 이 결정으로 대체한다.
- Supabase pgmq Basic Queue와 DB 작업 상태를 영속 원본으로 사용한다. 비공개 Realtime은 깨우기 신호다. 가정별 직렬 실행, 90초 임대·20초 갱신, 60초 보정 조회를 사용한다. 임대 만료는 unknown으로 전환한다. 변경 기록이 없는 작업은 원자적 완료 규칙상 재고가 바뀌지 않았음을 확인해 실패로 정리하고, 변경 기록이 있는 작업은 수동 확인까지 막는다. 자동 재실행하지 않는다.
- 맥미니 코드는 루트 `ai-gateway/`에 둔다. 맥미니에 설치된 Hermes 실행기와 관리 런타임을 사용한다(연결 확인 커밋 `c314285f077e91937c995d419b9fa40af9eb4981`). `kimjipsa` 전용 프로필을 만들고 기존 기본 프로필의 모델 설정과 Hermes 공용 인증 저장소를 사용한다. 개인 대화·기억·메신저 설정은 복사하지 않는다. 전용 API는 127.0.0.1:8643, 워커 상태는 127.0.0.1:8644다.
- Hermes 범용 도구를 비활성화한다. 읽기 문맥은 작업에 묶인 RPC로 공급하고 구조화된 변경 결과를 같은 권한의 완료 RPC가 실행한다. SQL 재고 규칙은 앱과 워커가 공유한다.
- Supabase가 공용 대화와 기억의 원본이다. 매 작업마다 전용 Hermes 실행 환경에 최신 문맥을 공급한다. 로컬 세션·사진·응답 저장소는 작업 종료 후 지운다. 프로필 설정과 식별 정보는 유지한다. 가족의 논리적 세션 ID는 고정하되 이전 로컬 기억에 의존하지 않는다.
- 모델 변경·인증 갱신은 맥미니 Hermes에서 수행하고 다음 실행에서 반영한다. 앱의 집사 설정 변경은 실행·대기 작업을 취소하며 이전 설정 버전의 결과 저장을 거부한다. 이미 적용된 마이그레이션은 유지하고 후속 마이그레이션에서 BYOK 등록·전송·선점 조건을 제거한다.

## 승인된 보관 정책

- 사진: 24시간 후 만료, 5분마다 Storage API로 삭제. 장애가 나면 다음 주기에 재시도. 가정 삭제 시에도 파일 경로를 별도 삭제 대기열에 남긴다.
- 영수증 초안: 7일 후 만료. 일반 변경 제안: 5분 후 만료.
- 대화 원문: 90일. 가족 기억: 삭제할 때까지. 수정·삭제·끄기 이후에는 이전 기억이 포함된 대화 문맥을 다시 주입하지 않는다.
- 구성원 탈퇴: 공유 대화·기억 유지, 작성자 FK를 null로 바꾸고 ‘탈퇴한 사용자’ 표시. 마지막 구성원 탈퇴: 가족 데이터 삭제 및 파일 정리 예약.

## 적용 상태와 제한

원격 마이그레이션·전용 워커 등록·두 사용자 검증은 별도 실행 단계다. 저장소의 기존 HTML/claude.ai 원본에는 개인별 정책이 남아 있으므로 다음 동기화 때 이 승인 내용을 함께 반영해야 한다. 그 전에는 최신 사용자 결정과 이 ADR의 공용 정책을 적용한다.

5분 유휴 후 요약 작업과 수동 기억 관리를 제공한다. 기억 변경 뒤 진행 중인 이전 요약은 취소한다. 두 기기 E2E 및 실제 모델·이미지 입력은 연결 후 검증해야 한다.
