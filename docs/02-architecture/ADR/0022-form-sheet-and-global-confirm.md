# 0022. 폼 시트 컴포넌트와 전역 확인창

Status: CONFIRMED (2026-11-12 사용자 승인)

## 맥락

- 편집 시트(일정, 재고 품목, 장바구니 항목, 재고 목록)마다 "변경 중 닫으면 저장할까요?" 확인, 머리의 취소·저장 버튼, 폼과 저장 버튼을 잇는 문자열 `form` id를 따로 구현한다. 문구도 화면마다 다르다.
- 휴대폰 뒤로가기로 시트를 닫는 처리는 일정 시트(`EventEditorSheet`)에만 있다.
- `ConfirmDialog`는 17개 파일에서 열림 상태와 마크업을 매번 직접 둔다.
- 시트는 겹쳐 열린다(일정 폼 위 날짜·시간 시트, 카테고리 시트 위 색 선택 시트, 시트 위 확인창). 날짜 시트처럼 폼 안에서 React Hook Form 컨텍스트를 쓰는 시트가 있다.

## 결정

- **시트는 선언형을 유지한다.** 화면 안에서 `<Sheet>`를 그린다. 전역 시트 호스트나 `useSheet().open(content)` 방식은 쓰지 않는다.
- **`shared/ui`에 `FormSheet`를 둔다.** `Sheet`를 감싸고 아래를 맡는다.
  - 머리의 취소(왼쪽)·제출(오른쪽) 버튼. 제출 문구는 `submitLabel`로 받는다(추가, 저장 등).
  - 폼 id를 안에서 만들어 제출 버튼과 연결한다. 호출하는 쪽은 문자열 id를 맞추지 않는다.
  - `dirty`일 때 닫으려 하면 저장 확인을 띄운다(문구 하나로 통일).
  - 뒤로가기로 시트 닫기(기존 `EventEditorSheet`의 history 처리 이전).
- **확인창은 전역으로 연다.** `app/providers`에 확인창 호스트 하나를 두고 `useConfirm()`이 `confirm(options): Promise<boolean>`을 돌려준다. 오래 걸리는 작업은 `onConfirm: async () => …`로 넘겨 확인창 안에서 진행 중 표시와 오류 문구를 보여 준다. 상태는 React `useState`와 Context로 둔다(스토어 라이브러리 추가 없음).
- 보기 전용 시트와 선택 시트(알림, 색 선택, 날짜·시간)는 지금처럼 `Sheet`를 쓴다.

## 대안

- 전역 시트 호스트(`useSheet`, event emitter): `useState` 한 줄을 줄이는 대신 겹쳐 열리는 시트를 위한 스택이 필요하고, 시트 내용이 폼 컨텍스트 밖에서 그려져 날짜 시트 같은 폼 안 시트가 깨진다. 모드에 따라 머리 버튼이 바뀌는 시트는 상태가 바뀔 때마다 전역에 다시 알려야 한다.
- 화면별 `ConfirmDialog` 유지: 진행 중 표시를 붙이기 쉽지만, 열림 상태와 마크업이 반복되고 문구가 어긋난다.

## 결과

- 편집 시트의 닫기 확인·뒤로가기·제출 연결이 한 곳에서 같은 동작을 한다. 재고·장바구니·목록 시트에도 뒤로가기 닫기가 생긴다.
- 확인창은 앱 전역 UI 상태가 된다. [상태 관리](../../03-guidelines/STATE_MANAGEMENT.md)의 "다이얼로그 열림은 Local State" 예시에서 확인창은 예외로 적는다.
- 전역 확인창이 열린 시트 위에서 포커스 가두기·바깥 클릭·ESC를 올바르게 처리하는지는 구현 때 테스트로 고정한다.
