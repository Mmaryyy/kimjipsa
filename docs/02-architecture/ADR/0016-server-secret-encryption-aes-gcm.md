# 0016. 서버 저장 비밀값 암호화: 앱 레벨 AES-GCM

- 결정 ID: ADR-0016 (관련 DEC: DEC-003, ACC-08)
- 결정 날짜: 2026-10-30
- 상태: Accepted

## 배경
AI 키(ACC-08)를 서버에 암호화해 저장해야 한다(DEC-003). 처음에는 P9b 구글 캘린더 토큰에 먼저 쓰려 했으나 CAL-15는 2026-10-30에 범위에서 제외했다. 사용자가 권장안 A를 승인했다(2026-10-30).

## 검토한 대안
- B. Supabase Vault: 키 관리를 Supabase가 하지만 암호화 키와 데이터가 같은 곳에 있다.
- C. 외부 KMS: MVP에는 비용과 구성이 과하다.

## 최종 결정
- Node 내장 `crypto`의 AES-256-GCM으로 서버 라우트에서만 암호화·복호화한다. 새 의존성은 없다.
- 마스터 키는 서버 전용 환경 변수 `SECRET_ENCRYPTION_KEY`(32바이트, base64)에 둔다. `.env.local`과 Vercel 환경 변수에 넣는다.
- 저장값에는 키 버전, IV, 인증 태그를 함께 넣어 나중에 키를 바꿀 때 재암호화할 수 있게 한다.
- 복호화한 값과 원문 토큰은 로그·응답·오류 메시지에 남기지 않는다. 브라우저로는 암호문도 내려보내지 않는다.

## 결정 이유
DB가 유출돼도 마스터 키 없이는 풀 수 없고, 의존성 없이 구현할 수 있다.

## 예상 영향
- 마스터 키를 잃으면 저장된 토큰을 쓸 수 없다. 이 경우 사용자가 다시 연결해야 한다.
- 키 교체 절차(새 버전으로 재암호화)는 필요할 때 정한다.
