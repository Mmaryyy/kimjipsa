# 0009. 로그인 수단별 별개 계정: 카카오 이메일 미수집 + 제공자 id 구분

- 결정 ID: ADR-0009 (관련 DEC: DEC-005)
- 결정 날짜: 2026-10-15
- 상태: Accepted

## 배경
명세 확정 정책은 카카오와 구글을 별개 계정으로 취급하고 합치지 않는다(ACC-01). Supabase Auth는 같은 이메일의 아이덴티티를 연결하는 동작이 있어, 같은 이메일로 두 수단을 쓰면 계정이 합쳐질 수 있다.

## 검토한 대안
- Supabase Auth의 자동 연결 설정을 조정한다.
- 계정 연결을 허용한다(명세 변경).

## 최종 결정
- 카카오 동의 항목에서 이메일을 받지 않는다.
- 계정은 제공자와 제공자 사용자 id로 구분하고, 이메일은 식별·연결에 쓰지 않는다. 화면에는 표시 이름(ACC-07)을 쓴다.
- Supabase가 실제로 이렇게 동작하는지(카카오 이메일 없이 로그인이 되는지, 같은 이메일의 구글과 합쳐지지 않는지)는 P2 초반에 시험해서 확인한다. 다르게 동작하면 구현을 멈추고 사용자에게 보고하고, 문서를 먼저 고친다.

## 결정 이유
사용자가 권장안을 선택했다. 명세 확정 정책을 바꾸지 않고, 이메일 연결이 일어날 조건 자체를 없앤다.

## 예상 영향
- `users` 스키마는 제공자와 제공자 사용자 id를 식별 키로 한다(`DATA_MODEL.md`).
- 이메일로 연락하거나 보여 주는 기능은 만들지 않는다.
- 카카오 앱 설정(동의 항목)이 이 결정에 맞아야 한다(보드의 "카카오 로그인 앱 만들기").
- Supabase의 카카오 provider가 이메일 없이 로그인을 거부하면 이 결정을 다시 검토한다.
