# 0018. Hermes 자체 기억과 Supabase 조회 스킬

Status: CONFIRMED (2026-11-04 사용자 요청 및 기억 별도 관리 선택)

## 결정

- `kimjipsa` 프로필의 Hermes 자체 기억·사용자 프로필 기억을 활성화한다. 앱과 디스코드는 같은 프로필의 기억을 사용할 수 있으며, 프로필을 담당하는 게이트웨이는 하나만 실행한다.
- Supabase의 가족 기억과 Hermes 기억은 별도로 관리한다. 앱의 기억 끄기·수정·삭제·초기화는 Supabase 기억에만 적용한다. Hermes 기억은 Hermes에서 관리한다. Supabase가 일정·재고·장바구니와 앱 기록의 원본인 점은 유지한다.
- `kimjipsa-supabase` 스킬과 읽기 전용 `kimjipsa_read` 도구를 제공한다. 워커 인증을 거친 서버가 연결된 가정의 가족 기억·재고·장바구니·일정을 조회한다. 도구에 SQL, DB 비밀번호, service_role, 임의 가정·사용자 지정 기능을 제공하지 않는다.
- 개인 일정 필터는 기존 서버 함수를 사용한다. 스킬은 개인 일정 제목·장소·메모, 개인 채팅·사진을 조회하지 못한다. ‘나만 보기’, 사진 처리, 웹 검색 결과 처리는 자체 기억이 꺼진 별도 임시 실행 공간을 사용한다.
- 공용 프로필의 기억·디스코드 설정·사용자 스킬은 작업 종료 시 삭제하거나 덮어쓰지 않는다. 앱 응답 형식 지시는 개별 API 요청에만 넣고, 프로필의 공통 지침은 일반적인 한국어 집사 지침으로 둔다.

## 대체하는 결정

ADR-0017의 Hermes 로컬 기억 비활성화, 범용 도구 전체 비활성화, 매 작업 뒤 공용 프로필 초기화를 대체한다. 앱 API에는 기억·스킬·가정 조회 도구만 허용하며 기존 변경 작업의 권한·확인 절차는 유지한다.

## 검증

기억 보존, 공용/개인 실행 공간 분리, 조회 도구의 인증·가정 격리·개인 일정 가림, Supabase 기억 끄기와 Hermes 기억의 독립성을 확인한다. 실제 디스코드 계정 연결과 모델 응답 검증은 설정·실행 결과와 구분해 보고한다.
