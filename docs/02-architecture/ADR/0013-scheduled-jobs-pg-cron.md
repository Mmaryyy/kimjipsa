# 0013. 예약 작업: Supabase pg_cron + 서버 라우트

- 결정 ID: ADR-0013 (관련 DEC: DEC-004, CAL-09~11, ACC-11)
- 결정 날짜: 2026-10-20
- 상태: Accepted

## 배경
아침 요약(CAL-10), 일정 시작 N분 전 알림(CAL-11), 이후 대화 요약(BOT-12)·90일 삭제(BOT-14)는 정해진 시각에 돌아야 한다. 서버리스(Vercel)에는 타이머가 없고, Vercel 무료 플랜 Cron은 실행 빈도 제한이 있어 분 단위 알림이 어렵다. 사용자가 권장안 A를 승인했다(2026-10-20).

## 검토한 대안
- B. Vercel Cron: 무료 플랜 빈도 제한으로 분 단위 알림을 보장하지 못한다.
- C. 외부 스케줄러 서비스: 계정·시크릿 관리가 하나 더 늘어난다.

## 최종 결정
- Supabase `pg_cron`이 1분마다 실행되고 `pg_net`으로 서버 라우트(예: `/api/cron/notifications`)를 호출한다.
- 호출은 공유 시크릿 헤더로 인증한다. 시크릿은 서버 환경 변수와 Supabase(Vault 또는 cron 설정)에만 두고 코드·로그에 남기지 않는다.
- 발송 대상 계산(사용자별 아침 요약 시각, 일정별 `remind_before`, 개인 일정은 작성자에게만)과 웹 푸시 발송은 서버 라우트가 맡는다. 같은 알림을 두 번 보내지 않도록 발송 기록으로 중복을 막는다.
- 시각 계산은 `Asia/Seoul` 기준이다(ADR-0004).

## 결정 이유
추가 서비스 없이 분 단위 실행이 되고, 발송 로직은 다른 서버 코드와 같은 곳에서 테스트할 수 있다.

## 예상 영향
- Supabase 프로젝트에서 `pg_cron`·`pg_net` 확장을 켜야 한다(사용자 할 일).
- P5 마이그레이션: 푸시 구독, 앱 내 알림, 발송 기록, cron 등록.
- 로컬 개발에서는 cron 대신 라우트를 직접 호출해 확인한다.
