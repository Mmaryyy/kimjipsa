김집사

신혼부부가 일정, 재고, 장바구니를 한곳에서 같이 관리하고, 그 데이터를 아는 AI 집사가 조회와 실행, 제안까지 해 주는 가정 관리 서비스. (kimjipsa는 개발용 코드명)

01한 줄 정의

부부가 함께 쓰는 일정, 재고, 장바구니를 하나로 묶고, AI 챗봇이 그 데이터를 바탕으로 질문에 답하고, 요청을 실행하고, 먼저 제안합니다.

02배경과 문제

핵심 페인 포인트는 세 가지입니다.

  1. 장 보러 갈 때 목록을 공유하고 정리하기 불편합니다. 메모앱과 카톡에 흩어져 있습니다.
  2. 이미 있는 걸 또 사거나, 떨어진 걸 모릅니다.
  3. 일정, 재고, 장보기가 여러 앱에 나뉘어 있어 한 앱에 모이길 원합니다.

03타깃과 사용자

구분 내용
1차 사용자 제작자 부부(도그푸딩), 이후 지인과 가족
장기 타깃 전 연령 가정. 역할은 관리자, 구성원, 자녀
MVP 권한 부부 둘 다 관리자(동등). 구성원과 자녀 역할은 구조만 열어 두고 UI는 후순위
주 사용 기기 스마트폰. 모바일 우선 PWA(반응형 웹)

04컨셉과 원칙

  • 모바일 우선 반응형 웹을 PWA로 구현합니다(MVP). 홈 화면에 설치해 앱처럼 쓰고, 웹 푸시도 PWA 기반입니다.
  • 공유가 기본, 비공개는 선택.
  • AI는 읽기는 자유롭게 하고, 사용자가 직접 요청한 변경은 바로 실행하며, AI가 스스로 판단한 변경만 채팅 안의 확인 버튼을 누른 뒤 실행.
  • 챗봇 이름은 사용자가 정합니다. 서비스 이름이 “김집사”이므로 챗봇은 성을 붙여 부릅니다. 예를 들어 “데비”를 고르면 챗봇은 “김데비”가 됩니다.
  • 무료 서비스. AI 비용은 가정이 부담하는 BYOK(사용자 본인 API 키) 방식입니다.

05기능 범위

MVP는 다섯 영역이고, 재정과 청소는 후순위입니다.

영역 핵심 기능
가정·계정 카카오·구글 로그인, 가정 생성, 초대 링크로 배우자 합류
일정 공유/개인(비공개) 일정, 기본 참석자 “둘 다”(스위치로 개인 전환), 카테고리, 종일·기간 일정, 장소·메모, D-day(기념일 통합, 축하 종류는 당일 홈에 축하 UI와 N주년 표시), 월간/주간/일간 뷰(홈 화면 뷰는 개인 설정)와 홈의 “다가오는 일정” 위젯, 삭제 전 확인 단계, 기본 카테고리({우리집 이름}, 회사, 가족, 약속, 병원, 기타)
재고 정확한 수량이 기본, 품목별 상태 모드(충분/부족/없음), 유통기한 선택 입력, 최소 수량 기준, 기본 단위 목록(사용자가 추가·수정·삭제), 기본 카테고리(식품 세분화, 생활용품, 건강·뷰티, 기타. 사용자 편집)와 보관 장소(냉장실, 냉동실, 실온 식품장·팬트리, 욕실·세탁실, 서랍·수납장을 기본 제공하고 “사용 안 함”이면 숨김) 입력, 보관 장소별 재고 조회, 등록은 직접 입력·챗봇·구매 완료 반영(M3에서 영수증 OCR: 등록한 AI로 품목 추출, AI가 기존 재고 연결을 제안하고 사용자가 확인), “다 썼어요” 버튼
장바구니 실시간 공동 편집·체크, 카테고리·마트 코너별 정렬, 자주 사는 품목 빠른 추가, 구매 완료 시 재고 반영(확인 화면), 외부 쇼핑몰 링크
AI 챗봇 일정·재고·장바구니 조회와 변경 도구, 서비스 연관 질문만 응답, 개인별 대화와 요약 기억, 챗봇 이름 직접 지정(“김○○”)
후순위 재정 관리, 청소·집안일 스케줄

06핵심 정책

일정은 공유가 기본이고, 비공개 내용은 화면과 챗봇 모두에서 차단합니다.

프라이버시

  • 개인 일정은 배우자에게 상태 아이콘과 희미한 색으로만 보입니다. 제목과 장소는 숨깁니다.
  • 챗봇은 도구 호출 단계에서 서버가 질문자 권한으로 데이터를 필터링합니다. 비공개 내용이 답변으로 나가지 않습니다.

편집 권한

  • 공동 일정은 둘 다 수정할 수 있고, 개인 일정은 작성자만 수정할 수 있습니다.

알림

  • MVP는 웹 푸시와 앱 내 알림 두 채널입니다. 추가 비용이 없습니다.
  • iOS에서 웹 푸시는 홈 화면에 추가한 PWA에서만 동작하므로, 온보딩에서 설치를 안내합니다.
  • 이메일과 카카오톡은 v1.1 이후에 검토합니다.
  • 일정 알림 매일 아침 당일 일정을 요약해서 보냅니다. 기본 발송 시각은 오전 10시이고 개인 설정에서 바꿀 수 있습니다. 일정별로 알림 시점을 직접 바꿀 수 있고, 기본값은 “시작 30분 전”입니다.
  • 재고 알림 푸시로는 보내지 않습니다. 부족하거나 유통기한이 임박한 품목은 홈 화면에 노출합니다.
  • 배우자 활동 알림 배우자가 일정을 등록하거나 변경했을 때만 받습니다. 장바구니 변경과 구매 완료는 알리지 않습니다.
  • AI 선제 제안 하루 최대 1회로 제한합니다. 주제는 일정 충돌·준비, 장보기, 재고 기반 제안입니다.

재고 단위

  • 개, 팩, 병 등 기본 단위 목록을 제공하고, 사용자가 가정 단위로 추가·수정·삭제할 수 있습니다. 사용 중인 단위를 지울 때는 품목 단위를 먼저 바꾸도록 안내합니다.

AI · BYOK

  • 관리자가 API 키를 한 번 등록하면 가정 전체가 공유합니다. 키는 서버에서 암호화 저장합니다.
  • AI 제공자는 사용자가 고릅니다. 관리자가 제공자(MVP는 Claude, Gemini)와 키를 하나만 등록하면 챗봇, 선제 제안, 영수증 OCR을 모두 그 키로 처리합니다. 비용도 그 키의 주인이 부담합니다.
  • 키가 없으면 AI 기능(자유 대화, OCR, 선제 제안)만 비활성화되고 나머지는 정상 동작합니다. 챗봇은 열리며, AI를 거치지 않는 기본 안내 메시지와 저장된 FAQ 답변은 계속 제공합니다.
  • 대화는 개인별로 분리하고, 지난 맥락은 요약해 토큰을 절감합니다.
  • 대화 원문은 90일 뒤 자동 삭제하고, 요약 기억은 대화가 끝날 때(5분 동안 새 대화가 없을 때) 갱신합니다.
  • 사용자는 설정에서 기억 목록을 보고, 항목별로 수정·삭제하고, 전체 초기화하거나 기억 기능을 끌 수 있습니다.
  • 사용자가 직접 요청한 변경은 바로 실행하고, 챗봇이 스스로 판단한 변경은 채팅 안에서 확인 버튼을 누른 뒤 실행합니다. 확인은 5분 안에 눌러야 합니다.

07핵심 UX 플로우

다섯 가지 플로우가 하루 사용의 대부분을 차지합니다.

  1. 온보딩(약 3분) 로그인 → 우리 집 만들기 → 카톡으로 초대 링크 공유 → 배우자 수락
  2. 홈 “오늘” 오늘 일정, D-day, 임박 재고, 장바구니 요약, 우하단 집사 아이콘(누르면 챗봇 채팅창)
  3. 일정 등록(기본 “둘 다”) → 개인 스위치 → 상대에게 반영
  4. 장보기 루프 소진(“다 썼어요”) → 장바구니 → 장보기(공동 체크) → 구매 완료 → 재고 반영 확인
  5. 챗봇 자연어 요청 → 의도 해석 → 실행(챗봇이 판단한 변경은 채팅 안에서 확인 후 실행)

혼자 개발하는 8주를 세 단계로 나눕니다.

M1 · 3주차까지

일정

  • 공유·개인 일정, D-day(기념일 통합, 축하 종류는 당일 홈에 축하 UI와 N주년 표시)
  • 월간/주간/일간 뷰, 다가오는 일정 위젯

재고 · AI

연동

09기술 구조

Next.js, Supabase, Vercel과 사용자가 등록한 AI API(Claude, Gemini)로 구성하는 안입니다.

브라우저는 로그인과 실시간 구독만 Supabase에 직접 연결하고, AI와 구글 캘린더 호출은 서버 라우트에서만 처리합니다. 키가 브라우저에 노출되지 않고, 챗봇도 질문자 권한으로 데이터를 거르기 위해서입니다. AI 호출은 제공자 차이를 감싸는 한 겹의 어댑터를 거쳐 등록된 제공자로 보냅니다.

코드는 Feature-Sliced Design(FSD)으로 구성합니다. 레이어는 app, pages, widgets, features, entities, shared이고 import는 위에서 아래로만 허용하며, 경계는 린트로 강제합니다. 일정, 재고, 장바구니 같은 도메인은 entities에, 사용자 행동은 features에 둡니다. 개인 일정 필터 같은 권한 규칙은 entities의 서버 함수 한 곳에 두어 화면과 챗봇이 함께 씁니다. 상세 구조는 개발 문서(docs/fsd.md)에서 관리합니다.

10성공 지표

첫 목표는 부부가 직접 계속 쓰는 것입니다. 아래 세 가지로 판단합니다(제안).

  • 4주 연속 매주 사용
  • 장보기 목록을 메모·카톡 대신 이 서비스로 관리
  • 재고 중복 구매 체감 감소

11리스크

가장 큰 두 가지는 개발 범위와 재고 데이터가 죽는 것입니다.

리스크 대응
구글 캘린더 쓰기 연동과 OCR은 개발량이 크고 정확도 이슈가 있음 M3에서 일정이 밀리면 구글 캘린더 쓰기, 선제 제안 순으로 v1.1로 이관
재고 입력이 귀찮아지면 데이터가 죽음 “다 썼어요” 버튼, 챗봇 입력, 구매 시 자동 반영으로 입력 부담 최소화
자체 도메인이 없으면 구글 로그인·캘린더 연동 승인이 막힘 (vercel.app은 소유 확인 불가) 구글 캘린더 연동(M3) 전에 자체 도메인 구입·연결
가족 데이터인데 이용약관·개인정보처리방침이 없으면 소셜 로그인 심사 등에 막히고 보호도 부족 베타 전 최소한의 약관·방침, 에러 모니터링, DB 백업 준비
제공자마다 도구 호출과 영수증 인식 품질이 달라 같은 기능이 다르게 동작할 수 있음 MVP는 Claude와 Gemini 두 곳만 지원하고, 어댑터로 감싸 출시 전에 핵심 시나리오를 제공자별로 점검

12아직 정해지지 않은 것

남은 미정 항목은 없습니다. 이번 라운드에서 아래를 확정했습니다.

확정: 재고 데이터 모델은 수량·상태 모드를 병행하고, 필드는 기능 명세의 재고 데이터 항목(name, mode, quantity/unit_id, status, min_quantity, category_id/location_id, expires_on)을 따릅니다.

확정: 지원 제공자는 Claude와 Gemini이고, MVP 출시 전에 챗봇 핵심 시나리오(조회, 직접 요청 실행, 확인 버튼)와 영수증 OCR을 제공자별로 점검합니다. 통과 기준은 점검표를 만들 때 정합니다.
