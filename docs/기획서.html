김집사

신혼부부가 일정, 재고, 장바구니를 한곳에서 같이 관리하고, 그 데이터를 아는 AI 집사가 조회와 실행, 제안까지 해 주는 가정 관리 서비스. (kimjipsa는 개발용 코드명)

01한 줄 정의

부부가 함께 쓰는 일정, 재고, 장바구니를 하나로 묶고, AI 챗봇이 그 데이터를 바탕으로 질문에 답하고, 요청을 실행하고, 먼저 제안합니다.

02배경과 문제

핵심 페인 포인트는 세 가지입니다.

  1. 장 보러 갈 때 목록을 공유하고 정리하기 불편합니다. 메모앱과 카톡에 흩어져 있습니다.
  2. 이미 있는 걸 또 사거나, 떨어진 걸 모릅니다.
  3. 일정, 재고, 장보기가 여러 앱에 나뉘어 있어 한 앱에 모이길 원합니다.

03타깃과 사용자

구분 내용
1차 사용자 제작자 부부(도그푸딩), 이후 지인과 가족
장기 타깃 전 연령 가정. 역할은 관리자, 구성원, 자녀
MVP 권한 부부 둘 다 관리자(동등). 구성원과 자녀 역할은 구조만 열어 두고 UI는 후순위
주 사용 기기 스마트폰. 모바일 우선 PWA(반응형 웹)

04컨셉과 원칙

  • 모바일 우선 반응형 웹을 PWA로 구현합니다(MVP). 홈 화면에 설치해 앱처럼 쓰고, 웹 푸시도 PWA 기반입니다.
  • 공유가 기본, 비공개는 선택.
  • AI는 읽기는 자유롭게 하고, 모든 변경은 직접 요청이라도 채팅 안 확인 메시지의 [확인]을 누른 뒤 실행(2026-11-05).
  • 챗봇 이름은 사용자가 정합니다. 서비스 이름이 “김집사”이므로 챗봇은 성을 붙여 부릅니다. 예를 들어 “데비”를 고르면 챗봇은 “김데비”가 됩니다.
  • 무료 서비스. AI 비용은 가정이 부담하는 BYOK(사용자 본인 API 키) 방식입니다.

05기능 범위

기존 다섯 영역에 가정 공유 프로젝트를 추가합니다. 프로젝트 안 예산·지출·정산을 제공하며, 별도 재정 관리와 청소는 후순위입니다.

영역 핵심 기능
프로젝트 영역·마일스톤·할 일·결정·목록·예약·일정표·예산·지출·정산
가정·계정 카카오·구글 로그인, 가정 생성, 초대 링크로 배우자 합류
일정 공유/개인(비공개) 일정, 기본 참석자 “둘 다”(스위치로 개인 전환), 카테고리, 종일·기간 일정, 장소·메모, D-day(기념일 통합, 축하 종류는 당일 홈에 축하 UI와 N주년 표시), 월간/주간/일간 뷰(홈 화면 뷰는 개인 설정)와 홈의 “다가오는 일정” 위젯, 삭제 전 확인 단계, 기본 카테고리({우리집 이름}, 회사, 가족, 약속, 병원, 기타)
재고 정확한 수량이 기본, 품목별 상태 모드(충분/부족/없음), 유통기한 선택 입력, 최소 수량 기준, 기본 단위 목록(사용자가 추가·수정·삭제), 기본 카테고리(식품 세분화, 생활용품, 건강·뷰티, 기타. 사용자 편집)와 보관 장소(냉장실, 냉동실, 실온 식품장·팬트리, 욕실·세탁실, 서랍·수납장을 기본 제공하고 “사용 안 함”이면 숨김) 입력, 보관 장소별 재고 조회, 등록은 직접 입력·챗봇·구매 완료 반영(M3에서 영수증 OCR: 등록한 AI로 품목 추출, AI가 기존 재고 연결을 제안하고 사용자가 확인), “다 썼어요” 버튼
장바구니 실시간 공동 편집·체크, 카테고리·마트 코너별 정렬, 자주 사는 품목 빠른 추가, 구매 완료 시 재고 반영(확인 화면), 외부 쇼핑몰 링크
AI 챗봇 일정·재고·장바구니 조회와 변경 도구, 서비스 연관 질문만 응답, 개인별 대화와 요약 기억, 챗봇 이름 직접 지정(“김○○”)
후순위 재정 관리, 청소·집안일 스케줄

06핵심 정책

일정은 공유가 기본이고, 비공개 내용은 화면과 챗봇 모두에서 차단합니다.

프라이버시

  • 개인 일정은 배우자에게 상태 아이콘과 희미한 색으로만 보입니다. 제목과 장소는 숨깁니다.
  • 챗봇은 도구 호출 단계에서 서버가 질문자 권한으로 데이터를 필터링합니다. 비공개 내용이 답변으로 나가지 않습니다.

편집 권한

  • 공동 일정은 둘 다 수정할 수 있고, 개인 일정은 작성자만 수정할 수 있습니다.

알림

  • MVP는 웹 푸시와 앱 내 알림 두 채널입니다. 추가 비용이 없습니다.
  • iOS에서 웹 푸시는 홈 화면에 추가한 PWA에서만 동작하므로, 온보딩에서 설치를 안내합니다.
  • 이메일과 카카오톡은 v1.1 이후에 검토합니다.
  • 일정 알림 매일 아침 당일 일정을 요약해서 보냅니다. 기본 발송 시각은 오전 10시이고 개인 설정에서 바꿀 수 있습니다. 일정별로 알림 시점을 직접 바꿀 수 있고, 기본값은 “시작 30분 전”입니다.
  • 재고 알림 푸시로는 보내지 않습니다. 부족하거나 유통기한이 임박한 품목은 홈 화면에 노출합니다.
  • 배우자 활동 알림 배우자가 일정을 등록하거나 변경했을 때만 받습니다. 장바구니 변경과 구매 완료는 알리지 않습니다.
  • AI 선제 제안 하루 최대 1회로 제한합니다. 주제는 일정 충돌·준비, 장보기, 재고 기반 제안입니다.

재고 단위

  • 개, 팩, 병 등 기본 단위 목록을 제공하고, 사용자가 가정 단위로 추가·수정·삭제할 수 있습니다. 사용 중인 단위를 지울 때는 품목 단위를 먼저 바꾸도록 안내합니다.

AI · BYOK

  • 관리자가 API 키를 한 번 등록하면 가정 전체가 공유합니다. 키는 서버에서 암호화 저장합니다.
  • AI 제공자는 사용자가 고릅니다. 관리자가 제공자(MVP는 Claude, Gemini)와 키를 하나만 등록하면 챗봇, 선제 제안, 영수증 OCR을 모두 그 키로 처리합니다. 비용도 그 키의 주인이 부담합니다.
  • 키가 없으면 AI 기능(자유 대화, OCR, 선제 제안)만 비활성화되고 나머지는 정상 동작합니다. 챗봇은 열리며, AI를 거치지 않는 기본 안내 메시지와 저장된 FAQ 답변은 계속 제공합니다.
  • 대화는 개인별로 분리하고, 지난 맥락은 요약해 토큰을 절감합니다.
  • 대화 원문은 90일 뒤 자동 삭제하고, 요약 기억은 대화가 끝날 때(5분 동안 새 대화가 없을 때) 갱신합니다.
  • 사용자는 설정에서 기억 목록을 보고, 항목별로 수정·삭제하고, 전체 초기화하거나 기억 기능을 끌 수 있습니다.
  • 챗봇의 모든 변경은 직접 요청이라도 채팅 안 확인 메시지의 [확인]을 누른 뒤 실행합니다(2026-11-05). 확인은 5분 안에 눌러야 합니다.

07핵심 UX 플로우

하단 탭은 오늘 · 일정 · 장보기 · 프로젝트 · 설정입니다. 장보기 안에서 장바구니와 재고를 전환합니다.

  1. 온보딩(약 3분) 로그인 → 우리 집 만들기 → 카톡으로 초대 링크 공유 → 배우자 수락
  2. 홈 “오늘” 오늘 일정, D-day, 임박 재고, 장바구니 요약, 우하단 집사 아이콘(누르면 챗봇 채팅창)
  3. 일정 등록(기본 “둘 다”) → 개인 스위치 → 상대에게 반영
  4. 장보기 루프 소진(“다 썼어요”) → 장바구니 → 장보기(공동 체크) → 구매 완료 → 재고 반영 확인
  5. 프로젝트 프로젝트 만들기 → 구성 요소 선택 → 할 일·결정·예약 관리 → 마감 확인
  6. 챗봇 자연어 요청 → 의도 해석 → 모든 변경은 확인 메시지 하나([확인][수정][취소]) → 실행

09기술 구조

Next.js, Supabase, Vercel과 사용자가 등록한 AI API(Claude, Gemini)로 구성하는 안입니다.

브라우저는 로그인과 실시간 구독만 Supabase에 직접 연결하고, AI 호출은 서버 라우트에서만 처리합니다. 키가 브라우저에 노출되지 않고, 챗봇도 질문자 권한으로 데이터를 거르기 위해서입니다. AI 호출은 제공자 차이를 감싸는 한 겹의 어댑터를 거쳐 등록된 제공자로 보냅니다.

코드는 Feature-Sliced Design(FSD)으로 구성합니다. 레이어는 app, pages, widgets, features, entities, shared이고 import는 위에서 아래로만 허용하며, 경계는 린트로 강제합니다. 일정, 재고, 장바구니 같은 도메인은 entities에, 사용자 행동은 features에 둡니다. 개인 일정 필터 같은 권한 규칙은 entities의 서버 함수 한 곳에 두어 화면과 챗봇이 함께 씁니다. 상세 구조는 개발 문서(docs/fsd.md)에서 관리합니다.

11리스크

가장 큰 두 가지는 개발 범위와 재고 데이터가 죽는 것입니다.

리스크 대응
OCR은 개발량이 크고 정확도 이슈가 있음 M3에서 일정이 밀리면 선제 제안을 v1.1로 이관
재고 입력이 귀찮아지면 데이터가 죽음 “다 썼어요” 버튼, 챗봇 입력, 구매 시 자동 반영으로 입력 부담 최소화
자체 도메인이 없으면 구글 로그인·캘린더 연동 승인이 막힘 (vercel.app은 소유 확인 불가) 구글 캘린더 연동은 범위에서 제외(2026-10-30). 구글 로그인은 vercel.app 기본 도메인으로 운영
가족 데이터인데 이용약관·개인정보처리방침이 없으면 소셜 로그인 심사 등에 막히고 보호도 부족 베타 전 최소한의 약관·방침, 에러 모니터링, DB 백업 준비
제공자마다 도구 호출과 영수증 인식 품질이 달라 같은 기능이 다르게 동작할 수 있음 MVP는 Claude와 Gemini 두 곳만 지원하고, 어댑터로 감싸 출시 전에 핵심 시나리오를 제공자별로 점검

12아직 정해지지 않은 것

남은 미정 항목은 없습니다. 이번 라운드에서 아래를 확정했습니다.

확정: 재고 데이터 모델은 수량·상태 모드를 병행하고, 필드는 기능 명세의 재고 데이터 항목(name, mode, quantity/unit_id, status, min_quantity, category_id/location_id, expires_on)을 따릅니다.

확정: 지원 제공자는 Claude와 Gemini이고, MVP 출시 전에 챗봇 핵심 시나리오(조회, 직접 요청 실행, 확인 버튼)와 영수증 OCR을 제공자별로 점검합니다. 통과 기준은 점검표를 만들 때 정합니다.

FEATURE · 프로젝트프로젝트 · PRJ-01~15

2026-11-18 사용자 계획 반영. 요구사항은 CONFIRMED이며 구현은 PJ1~PJ7에서 진행한다. 데이터 구조 ADR-0023과 HTML 시안은 PROPOSED(사용자 승인 대기)다.

가정 안의 몇 달씩 이어지는 일(결혼 준비·이사·인테리어)을 영역과 구성 요소로 관리한다. 할 일·마일스톤은 항상 켜고 결정·목록·예약·일정표·예산/지출/정산은 선택한다. 사진은 브라우저에서 줄여 Supabase Storage의 가정 권한 경로에 저장한다. 진행률·다가오는 마감·예산 합계/상한 대비·월별·정산·후보 예상 총액·예약 겹침은 계산하며 저장하지 않는다. 프로젝트 안 예산과 P19 재정 관리의 연결은 이후 범위다.

PRJ-01 프로젝트 CRUD — 이름(필수)·설명·시작일·목표일·상태(진행 중/완료/보관)·켤 구성 요소를 관리한다. 가정 전체 공유만 제공하며 개인 프로젝트는 없다. 할 일·마일스톤은 항상 켠다. 구성 요소를 끄면 데이터는 삭제하지 않고 숨긴다. 삭제는 프로젝트 이름이 적힌 확인 화면을 거친다. PJ2
PRJ-02 영역 — 프로젝트 안 하위 묶음을 추가·수정·삭제하고 순서를 바꾼다. 영역 삭제 시 소속 항목은 삭제하지 않고 영역 없음으로 옮긴다. PJ2
PRJ-03 마일스톤·타임라인 — 제목·시작/종료일 또는 미정·메모를 관리한다. 마일스톤 순서와 영역별 진행률로 타임라인을 보여 주고 지금 시기를 강조한다. PJ2
PRJ-04 할 일 — 제목·영역·담당(미정/함께/가정 구성원)·상태(미시작/진행 중/완료/보류)·시작일·마감일·선행 조건(글)·메모를 관리한다. 완료 토글, 미완료 먼저·완료 접기, 영역·상태·담당 필터와 검색을 제공한다. PJ2
PRJ-05 결정 — 질문·상태(논의 중/결정 완료/보류)·기한·후보(글)·구성원별 의견·최종 선택을 관리한다. 구성원 수만큼 의견 칸을 둔다. PJ3
PRJ-06 후보 목록 — 목록 이름·사용자 정의 칸(글/숫자/금액/선택)을 관리한다. 수량 기준은 선택이며 같은 프로젝트의 명단 하나와 그 명단의 태그 하나를 함께 지정한다. 후보는 이름·가격·링크 여러 개·사진·상태(후보/선택/제외)·칸 값·메모를 가진다. 예상 총액은 가격 × 지정 명단에서 해당 태그가 붙은 인원이며 가격이 없으면 가격 미정이다. 연결된 명단이나 태그를 지우면 두 연결을 해제하고 수량 기준 없음으로 표시한다(r001-f1). PJ4
PRJ-07 명단 — 목록 이름·사용자 정의 칸·태그 목록을 관리한다. 사람마다 이름·칸 값·복수 태그·태그별 완료·메모를 저장한다. 태그별 대상 수와 완료 수를 집계한다. PJ4
PRJ-08 예약 — 제목·종류(숙소/교통/식당/체험/기타)·상태(검토 중/예약 예정/예약 완료/취소)·이용 시작/종료·예약 번호·링크·무료 취소 마감·결제 마감·총액·결제액·메모를 관리한다. 결제액은 총액 이하다. 같은 프로젝트·같은 종류의 기간 겹침을 경고하고 취소된 예약은 비교에서 뺀다. PJ3
PRJ-09 일정표 — 날짜(필수)·종료일·장소·내용·링크·메모를 관리하며 날짜순으로 보여 준다. 특정 여행 기간으로 제한하지 않는다. PJ3
PRJ-10 예산·지출·정산 — 예산 상한은 선택이다. 지출은 제목·영역·예상액·예상 결제일·실제액·실제 결제일·결제자·공동/개인/미정·링크·메모를 가진다. 실제액이 있으면 결제일·결제자가 필수다. 예상·실제·상한 대비·월별 요약과 구성원별 분담 비율(합 100%) 정산을 제공한다. 비율 없음, 비율 합이 100% 아님(탈퇴로 비율 행이 지워진 경우 포함), 결제한 지출의 공동/개인 미정, 결제한 공동 지출의 결제자 없음(탈퇴) 중 하나라도 있으면 정산 보류와 이유를 표시한다. 실제 지출 기록은 탈퇴해도 지우지 않는다(r001-f2). PJ5
PRJ-11 일정에 추가 — 마일스톤·예약·일정표의 일정에 추가 버튼으로 실제 공유 일정을 만들고 연결한다. 알림·챗봇 조회는 기존 일정 기능을 따른다. 연결된 일정이 지워지면 연결만 해제하고 프로젝트 항목은 유지한다. PJ3
PRJ-12 알림 — 진행 중 프로젝트에만 적용한다. 내 할 일(담당 나 또는 함께) 마감 전날은 해당 담당자에게, 결정 기한·예약 무료 취소/결제 마감 전날은 가정 전원에게 알린다. 아침 요약에 오늘 마감인 프로젝트 항목을 한 줄 포함한다. 기존 사용자별 푸시 on/off를 따른다. PJ6
PRJ-13 홈 마감 카드 — 진행 중 프로젝트에서 7일 안에 마감되는 할 일·결정·예약을 최대 5개 보여 준다. 홈 설정에서 켜고 끈다. PJ6
PRJ-14 챗봇 — 프로젝트·할 일·결정·예약·지출을 조회하고 할 일 추가·완료와 지출 기록을 지원한다. 현행 BOT-07에 따라 직접 요청을 포함한 모든 변경은 채팅 안 확인 메시지 하나([확인][수정][취소])를 거친 뒤 실행한다. PJ6
PRJ-15 진행 차트 — 프로젝트 개요에 마일스톤 간트 차트와 영역별 할 일 칸 차트를 보여 준다. 간트: 기간이 있는 마일스톤을 시간축 막대로 그리고 오늘 위치를 세로선으로 표시한다. 기간 미정 마일스톤은 막대 없이 따로 둔다. 모바일은 월 눈금 한 줄의 얇은 형태, 데스크톱은 넓은 형태다. 칸 차트: 영역별 진행률 막대를 대신해 할 일 하나를 칸 하나로 그리고 상태(완료/진행 중/미시작/ 보류)별로 색을 나눈다. 새 데이터 없이 기존 마일스톤·할 일로 그린다. 정해야 할 것: 할 일이 많을 때 칸 표시 방식, 간트 시간축 범위·확대. 확인 시나리오

SCN-PRJ-1 · 프로젝트·영역·할 일프로젝트를 만들고 영역·날짜 미정 마일스톤·함께 담당 할 일을 추가한다. 완료하면 진행률이 바뀌고 완료 묶음으로 이동한다. 영역 삭제 후 할 일은 영역 없음에 남는다. 다른 가정은 조회·수정할 수 없다.
SCN-PRJ-2 · 결정·예약·일정표구성원별 의견을 남기고, 같은 종류의 예약 기간이 겹치면 경고를 본다. 취소 예약은 제외된다. 마일스톤·예약·일정표 각각에서 공유 일정 생성·연결 후 해당 일정을 삭제하면 연결만 해제된다.
SCN-PRJ-3 · 명단·후보 수량명단 A의 답례품 태그 인원이 2명이면 12,000원 후보의 예상 총액은 24,000원이다. 명단 B의 같은 이름 태그 인원은 합치지 않는다. 명단 A 또는 해당 태그 삭제 시 수량 기준 없음으로 바뀐다. 가격 없는 후보는 가격 미정이다.
SCN-PRJ-4 · 정산 보류·탈퇴비율 없음·비율 합 100 아님·결제한 지출의 공동/개인 미정·결제한 공동 지출 결제자 없음의 네 경우를 각각 확인한다. 보류 이유를 모두 표시하고 탈퇴 후에도 실제 지출 기록·금액이 남는다.
SCN-PRJ-5 · 알림·홈·집사진행 중 프로젝트의 나/함께 할 일·결정·예약 마감 전날 수신자와 푸시 설정을 확인한다. 아침 요약 한 줄과 홈 7일·최대 5개·설정 끄기를 확인한다. 집사의 조회와 변경을 구분하고, 할 일 추가·완료와 지출 기록은 직접 요청도 확인 메시지 하나([확인][수정][취소])를 거치는지 확인한다.
SCN-PRJ-6 · 탭·최소화375px /inventory에서는 장보기만, 1280px 사이드에서는 재고만 선택된다. 최소화 전후 하단 5/6개·사이드 6/7개이고 장보기 세그먼트가 두 주소를 유지한다.
