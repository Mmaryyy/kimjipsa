# 운영 공지 푸시 보내는 법

상태: 운영자용 일회성 스크립트(사용자 요청 2026-11-12). 앱 기능이 아니라 요구사항 ID가 없다. 앱 안 알림 목록에는 남지 않고, 푸시를 켠 기기에만 간다.

## 한눈에

```bash
yarn announce                                   # 1) 미리보기: 루트 announce.md를 읽고 받을 기기 수만 보여 줌
yarn announce --send                            # 2) 바로 발송
yarn announce --at "2026-11-13 09:00" --send    # 3) 예약 발송(KST)
```

`--send`가 없으면 절대 보내지 않는다. 항상 미리보기로 제목·내용·받을 기기 수를 확인한 뒤 `--send`를 붙인다.

## 공지 파일 쓰기

- 첫 줄이 제목, 그 아래가 내용이다. 제목 다음 빈 줄은 있어도 없어도 된다.
- 이모지·줄바꿈을 그대로 쓴다. UTF-8 텍스트 파일이면 된다.
- 기본 파일은 저장소 루트의 `announce.md`다. `.gitignore`에 있어 커밋되지 않는다. 다른 파일은 `--file <경로>`로 지정한다.
- 첫 줄을 `# 제목`처럼 마크다운 제목으로 써도 된다(`#`은 떼고 보낸다). 내용의 마크다운 문법은 변환하지 않고 글자 그대로 나간다.
- 내용은 600자에서 잘린다. 잠금화면에 보이는 줄 수는 기기마다 다르다(iOS는 보통 4줄 안팎). 중요한 말은 첫 줄에 쓴다.

```
# 🎉 김집사 업데이트 안내

일정 확인 화면이 새로워졌어요 ✨
- 재고는 왼쪽으로 밀어서 다 씀 처리 📦
```

## 옵션

| 옵션                       | 뜻                                                          | 기본값       |
| -------------------------- | ----------------------------------------------------------- | ------------ |
| `--file <경로>`            | 공지 파일(첫 줄 제목, 나머지 내용)                          | `announce.md` |
| `--title "…"` `--body "…"` | 파일 없이 바로 쓰기. 파일과 같이 주면 이 값이 우선          | 없음         |
| `--url /경로`              | 알림을 눌렀을 때 열 앱 안 경로(예: `/cart`). 외부 주소 불가 | `/`(홈)      |
| `--at "YYYY-MM-DD HH:mm[:ss]"` | 이 시각(KST)까지 기다렸다 보냄. 초는 선택. 지난 시각은 거부 | 즉시         |
| `--send`                   | 실제 발송. 없으면 미리보기만                                | 미리보기     |

## 예약 발송 주의

- 웹 푸시에는 예약 기능이 없어서 스크립트가 그 시각까지 기다린다. 실행한 터미널(프로세스)이 그때까지 살아 있어야 한다.
- 맥북이 잠들면 깨어날 때까지 발송이 밀린다. 정확한 시각이 필요하면 항상 켜져 있는 맥미니에서 돌린다(맥미니에 저장소와 아래 `.env.local` 값이 있어야 한다).
- 기다리는 동안 취소하려면 그 터미널에서 Ctrl+C.

## 준비물

- 저장소 루트의 `.env.local`에 `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`(`mailto:`로 시작)가 있어야 한다. 하나라도 없으면 스크립트가 이름을 알려 주고 멈춘다.
- 알림 제목이 보이려면 `public/sw.js`의 제목 처리(2026-11-12)가 배포돼 있어야 한다. 배포 전이거나 기기의 서비스 워커가 아직 옛 버전이면 제목은 "일정 알림"으로 나오고 내용만 공지 문구로 보인다.

## 결과 읽기

마지막 줄에 `성공 n, 만료된 구독 n, 실패 n`이 나온다.

- 만료된 구독: 앱을 지웠거나 알림을 끈 기기다. 건너뛴다(정리는 앱의 예약 알림 작업이 다음 발송 때 한다).
- 실패가 있으면 종료 코드 1로 끝나고 상태 코드만 출력한다(구독 주소·키는 출력하지 않는다). 잠시 뒤 다시 보내면 성공한 기기에도 한 번 더 간다는 점에 주의한다.

## 관련 파일

- 스크립트: `scripts/send-announcement.mjs` (`package.json`의 `announce`)
- 서비스 워커 표시: `public/sw.js`
- 구독 저장: `push_subscriptions` 테이블(`supabase/migrations/20261021010000_web_push.sql`)
