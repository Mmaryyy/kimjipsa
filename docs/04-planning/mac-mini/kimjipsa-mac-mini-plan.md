# 김집사 맥미니 구현 계획

맥미니 M4에서 가족용 Hermes 프로필과 Realtime 워커를 운영한다. 새 작업 수신, AI 실행, 김집사 도구 호출, 가족 기억 연결, 재시작 복구와 로컬 임시 파일 정리를 맡는다. 초기 대상은 한 가정의 사용자 2명이다.

기준일: 2026년 11월 4일 · [전체 계획 Page](https://chatgpt.com/space/page_8dd8c181ebb48191ae73df465d86df94)

API·이벤트·작업 상태·진행 순서·확정할 정책은 [공통 연동 규약](./kimjipsa-integration-contract.md)을 따른다. 서버와 화면의 구현은 [앱과 클라우드 구현 계획](./kimjipsa-app-plan.md)에 구분했다.

이 영역은 맥미니의 Hermes 설치·전용 워커·가족 프로필·로컬 데이터 운영에서 구현한다.

## M1 Hermes와 가족 프로필 준비

- [ ] 구축 시점의 안정 버전을 확인해 고정하고 모델의 텍스트·이미지 입력을 확인한다.

- [ ] 가족 ID에 대응하는 프로필 하나와 API 전용 공용 세션을 만든다. 운영자의 개인 프로필이나 CLI 대화는 재사용하지 않는다.

- [ ] Hermes API를 127.0.0.1에만 바인딩하고 인증 키를 설정한다. 외부 공개 포트를 열지 않는다.

- [ ] 가족 집사 성격과 서비스 범위를 설정하고, 김집사 도구만 허용한다.

- [ ] 범용 터미널·파일·임의 SQL 도구는 기본 비활성화한다. 프로필은 상태 분리이며 파일 접근 샌드박스는 아니다.

Hermes는 OpenAI 호환 HTTP API와 이미지 입력, 실행 상태·진행 이벤트를 제공한다. 구축 버전에서 텍스트·사진·세션 이어가기·재접속의 실제 조합을 먼저 확인해 워커 어댑터를 고정한다. [Hermes API](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server), [프로필과 격리 범위](https://hermes-agent.nousresearch.com/docs/user-guide/profiles)

## M2 Realtime 워커 구현

- [ ] 맥미니 전용 인증으로 워커 채널 하나를 구독한다. 워커 자격은 Keychain 등 OS 비밀 저장소에 보관하고 설정 예시에 실제 값을 넣지 않는다.

- [ ] 구독 완료 직후 대기열을 조회하고, 새 알림을 받으면 작업 선점 RPC를 호출한다.

- [ ] 하나의 알림에만 의존하지 않고 처리 가능한 작업을 반복해서 가져와 대기열을 비운다.

- [ ] 가족의 실행 슬롯을 확보하고 같은 가족 작업은 직렬 처리한다. 초기 전체 동시 실행은 1개로 시작한다.

- [ ] 처리 임대를 갱신하고 진행 상태·오류·결과를 인증된 RPC로 저장한다. 마지막 정상 통신 시각을 갱신해 앱이 오프라인 상태를 구분하게 한다.

- [ ] 설정 버전 변경을 감지해 가족 프로필과 키를 다음 작업 전에 갱신한다.

- [ ] 상시 짧은 폴링을 주 전달 방식으로 쓰지 않는다. 시작·재연결·작업 완료 시 보정 조회하고 오래 대기한 작업을 복구하는 저빈도 점검을 둔다.

## M3 Hermes 실행 어댑터

- [ ] 작업 ID와 가족 대화를 Hermes의 요청·세션 ID에 연결한다.

- [ ] 중복 방지 헤더와 실행 참조를 저장해 네트워크 오류 뒤에 새 작업을 무조건 만들지 않게 한다.

- [ ] 메시지·가족 기억·승인된 첨부만 입력에 포함한다.

- [ ] 진행 이벤트를 사진 읽는 중, 재고 확인 중, 초안 준비 중 같은 제한된 앱 상태로 변환한다.

- [ ] 자유 텍스트와 영수증 결과는 앱에서 합의한 JSON 형태로 검증한다. 임의 HTML을 결과 카드로 전달하지 않는다.

- [ ] Hermes의 정상 완료·실패·중단·상태 불명을 구분해 전달한다. 최종 텍스트가 도착했다는 이유만으로 성공 처리하지 않는다.

텍스트 실행에는 Runs API를 활용할 수 있고, 이미지 입력은 Chat Completions 또는 Responses의 지원 형식을 사용한다. 이미지 요청의 실행 참조와 재시도 방식은 M1 연결 확인에서 확정한다. 앱의 작업 규약은 Hermes 내부의 엔드포인트 선택과 분리한다.

## M4 김집사 도구와 영수증 분석 연결

- [ ] 재고 조회·수량 등록·영수증 초안 저장·기억 조회 도구를 가족 전용 API에 연결한다.

- [ ] 도구 인증은 현재 작업과 가족에 묶고, 모델이 임의 가정 ID나 API 주소를 선택하지 못하게 한다.

- [ ] 실행 시 사진 접근 권한과 만료를 확인해 다운로드하거나 이미지 입력으로 전달한다.

- [ ] 품목별 원문 이름·정규화 이름·수량·단위·연결 후보·확인 필요 사유를 추출한다.

- [ ] 가격을 수량으로 오인하거나 팩과 개를 임의 변환하지 않는다. 불확실한 항목은 확인 카드로 보낸다.

- [ ] 영수증 자체에 없는 유통기한과 보관 장소는 확정값으로 저장하지 않는다.

- [ ] 분석 결과는 초안으로 저장하고, 사진 등록 요청만으로 재고 반영까지 완료됐다고 답하지 않는다.

## M5 가족 기억 어댑터

- [ ] Supabase의 해당 가족 기억만 Hermes에 공급한다.

- [ ] 기억 수정·삭제·끄기·초기화 버전을 감지해 다음 대화에 반영한다.

- [ ] Hermes 기본 로컬 기억과 앱 기억이 독립적으로 쌓이지 않도록 공급·저장 경로를 통합한다.

- [ ] 가족 공유 대화와 처리 결과는 공용 맥락으로 이어가되 원본 영수증을 장기 기억으로 별도 보관하지 않는다.

## M6 재시작과 로컬 정리

- [ ] 워커와 Hermes를 launchd로 관리하고 부팅·로그인·프로세스 장애 뒤의 재기동 절차를 만든다.

- [ ] 실제 재시작과 재로그인 조건을 확인하고 절전 방지·서비스 로그·상태 확인 방법을 운영 안내에 적는다.

- [ ] 진행 중이던 작업은 저장된 Hermes 참조와 도구 실행 기록을 먼저 확인한다.

- [ ] 결과가 불명확하면 unknown 상태로 두고 재고 변경을 무조건 반복하지 않는다.

- [ ] 로컬 사진을 받았다면 성공·실패 뒤 임시 파일을 삭제하고, 시작할 때 남은 임시 파일도 정리한다.

- [ ] 대화 보존 기한과 가족 삭제 요청에 따라 로컬 세션·응답 저장소·관련 캐시를 정리한다.

- [ ] 로그에는 작업 ID·상태·시간·오류 코드 위주로 남기고 키·사진 원본·전체 도구 응답은 남기지 않는다.

macOS의 기본 LaunchAgent는 사용자 로그인과 연결되므로 재부팅 뒤 로그인 전까지의 가용성도 실제 운영 조건에 포함한다.
