# 김집사 앱과 클라우드 구현 계획

김집사 Next.js PWA와 Vercel·Supabase에서 가족 공용 채팅, 영수증 확인·재고 반영, 인증·저장·사진 삭제를 구현한다. 초기 대상은 한 가정의 사용자 2명이며 두 사람은 같은 집사·대화·기억을 공유한다.

기준일: 2026년 11월 4일 · [전체 계획 Page](https://chatgpt.com/space/page_8dd8c181ebb48191ae73df465d86df94)

API·이벤트·작업 상태·진행 순서·확정할 정책은 [공통 연동 규약](./kimjipsa-integration-contract.md)을 따른다. 연결 상대의 작업은 [맥미니 구현 계획](./kimjipsa-mac-mini-plan.md)에 구분했다.

## 재사용할 앱 기반

현재 저장소에는 재고 조회·쓰기와 단위·카테고리·보관 장소 관리, 장바구니 구매 후 재고 반영 UI와 RPC가 있다. 재고 기반을 다시 만드는 대신 이를 재사용한다. 현재 재고 서버 함수는 브라우저 쿠키 세션을 전제로 하므로, 워커용 인증 문맥을 받아 공통 도메인 로직을 호출하는 경로를 별도로 마련한다.

- [재고 서버 구현](https://github.com/Mmaryyy/kimjipsa/blob/b74005aa2a90161fdd847a25401f6a80bf0e35bb/src/entities/inventory-item/api/server.ts)

- [구매 후 재고 반영 UI](https://github.com/Mmaryyy/kimjipsa/blob/b74005aa2a90161fdd847a25401f6a80bf0e35bb/src/features/cart-checkout/ui/restock-page/Form.tsx)

- [승인된 AES 256 GCM 암호화 정책](https://github.com/Mmaryyy/kimjipsa/blob/b74005aa2a90161fdd847a25401f6a80bf0e35bb/docs/02-architecture/ADR/0016-server-secret-encryption-aes-gcm.md)

- [승인된 pg_cron 예약 작업 정책](https://github.com/Mmaryyy/kimjipsa/blob/b74005aa2a90161fdd847a25401f6a80bf0e35bb/docs/02-architecture/ADR/0013-scheduled-jobs-pg-cron.md)

기존 명세의 개인별 챗봇 대화·기억 정책은 가족 공용 정책으로 갱신한다. 일정 도구를 추가할 때는 개인 일정 필터와 가족 집사 접근 범위가 일치하도록 별도 변경 범위를 정리한다.

이 영역은 김집사 저장소와 Vercel·Supabase 설정에서 구현한다.

## A1 요구사항과 서버 역할 정리

- [ ] BOT의 개인별 대화·기억 정책을 가족 공용으로 반영하고 데이터 모델·API 규칙·로드맵을 맞춘다.

- [ ] Vercel이 인증과 키 관리를 맡고, 맥미니가 신뢰된 AI 실행 백엔드로 참여하는 구조를 ADR에 기록한다.

- [ ] 기존 재고 등록·병합·단위 검증과 구매 후 재고 반영 로직 중 재사용할 부분을 구분한다.

- [ ] 가정 탈퇴·삭제 때 공유 대화와 기억을 어떻게 처리할지 명시한다.

## A2 영속 데이터와 작업 대기열

테이블 이름과 필드는 설계 제안이다. 기존 재고 테이블과 회원·가정 모델은 유지한다.

| 데이터 | 주요 내용 |
| --- | --- |
| ai_settings | 가정별 제공자·암호화한 키·집사 이름·기억 설정·설정 버전 |
| family_agents | 가정과 Hermes 프로필·공용 대화·Hermes 세션 연결 |
| agent_workers | 등록된 워커 인증 주체·연결 대상·마지막 정상 통신 시각 |
| chat_messages | 가정·공용 대화·순서 번호·작성자·역할·본문·첨부·결과 카드 |
| agent_runs | 요청 메시지·작업 유형·상태·Hermes 실행 참조·중복 방지 키·처리 임대·오류 코드 |
| agent_actions | 작업별 재고 변경 식별자·검증된 입력·실행 결과. 도구 재호출 시 같은 결과 반환 |
| chat_attachments | 가정·Storage 경로·형식·크기·처리 상태·만료 시각·삭제 완료 시각 |
| receipt_imports | 영수증 품목 초안·연결 후보·수정 버전·확인자·반영 상태·결과 |
| family_memories | 가족 공용 기억·수정 버전·기억 사용 설정 |

- [ ] Supabase Queues의 영속 Basic Queue를 사용하고 큐에는 작업 ID만 넣는다.

- [ ] 사용자 메시지 저장, 작업 생성, 큐 등록을 한 DB 트랜잭션으로 처리한다.

- [ ] 가정과 clientRequestId에 고유 제약을 두어 중복 전송을 같은 작업으로 처리한다.

- [ ] 작업 선점·임대 갱신·완료·실패 RPC를 만들고 등록된 워커만 호출하도록 제한한다.

- [ ] 같은 가정에서는 한 작업씩 순서대로 처리한다. 임대 세대와 토큰을 검사해 재시작 전의 오래된 실행이 결과를 덮어쓰지 못하게 한다.

- [ ] 완료된 결과를 DB에 저장한 뒤 큐 작업을 확인 처리한다. 전체 조회·선점·삭제 권한을 브라우저에 공개하지 않는다.

## A3 비공개 Realtime과 인증

| 채널 제안 | 구독자 | 내용 |
| --- | --- | --- |
| family:<family_id>:chat | 해당 가정 구성원 | 메시지·작업·영수증 초안 변경 알림 |
| worker:<worker_id>:jobs | 등록된 맥미니 워커 | 새 작업과 설정 변경 알림 |

- [ ] 가정 멤버십과 워커 등록 정보를 기반으로 테이블·채널·파일에 RLS를 적용한다.

- [ ] 앱은 로그인한 가정의 비공개 채널만 구독하고, 일반 사용자의 워커 채널 접근을 차단한다.

- [ ] 시스템 알림은 DB·서버에서 발행한다. 사용자가 임의의 집사 답변이나 완료 이벤트를 만들 수 없게 한다.

- [ ] 알림에는 작업·메시지·초안 ID와 버전을 싣고, 원문 사진·API 키·워커 비밀값은 싣지 않는다.

- [ ] 브라우저에서 Supabase 클라이언트를 재사용하고, 로그아웃·재접속 때 구독과 캐시를 정리한다.

Realtime 비공개 채널은 구독 설정과 권한 정책을 함께 구성해야 한다. [Realtime 권한](https://supabase.com/docs/guides/realtime/authorization)

## A4 가족 공용 채팅 화면

- [ ] 모든 주요 화면에서 같은 공용 채팅을 열도록 한다. 모바일은 넓은 채팅 화면, PC는 오른쪽 패널을 기본안으로 둔다.

- [ ] 사용자 이름·전송 시각·사진·집사 답변·구조화된 결과 카드를 표시한다.

- [ ] 메시지 접수 후 대기 중, 처리 중, 확인 필요, 완료, 실패 상태를 표시한다.

- [ ] 초기에는 상태 변경과 완성된 답변 위주로 전달한다. 토큰마다 DB를 갱신하지 않는다.

- [ ] 앱 시작·재접속 때 마지막 순서 번호 이후의 메시지를 조회해 빠진 내용을 복구한다.

- [ ] AI 키가 없어도 기본 안내와 저장된 FAQ는 표시하고, 자유 질문에는 키 등록 안내를 제공한다.

- [ ] 맥미니가 오프라인이면 즉시 처리된 것처럼 표시하지 않고 대기·취소·실패 상태를 구분한다.

## A5 재고 도구와 영수증 확인 카드

- [ ] 기존 재고 서버 함수의 도메인 규칙을 공통화하고, 워커가 작업에 묶인 권한으로 호출하는 도구 API를 만든다.

- [ ] 모델이 전달한 family_id나 user_id로 실행 권한을 결정하지 않는다. 서버가 작업과 가정의 연결을 검증한다.

- [ ] 재고 조회, 명확한 수량 추가, 영수증 초안 저장 기능을 1차 도구로 제공한다.

- [ ] 영수증 카드에서 품목 선택·이름·수량·단위·기존 품목 연결·카테고리·보관 장소·선택 유통기한을 수정하게 한다.

- [ ] 이름 비교는 기존 normalizeItemName과 compareItemNames 기준을 재사용한다. 유사 후보는 사용자에게 선택하게 한다.

- [ ] 확인은 초안 버전과 상태를 검사한 뒤 재고 증가·신규 생성·반영 완료 기록을 한 트랜잭션으로 저장한다.

- [ ] 직접 요청 도구도 작업별 변경 식별자와 agent_actions 실행 기록을 재고 변경과 같은 트랜잭션에 저장해 재호출 시 중복 반영하지 않는다.

- [ ] 같은 영수증 초안을 두 사람이 확인하거나 버튼을 재시도해도 한 번만 반영한다. 이미 완료된 요청은 같은 완료 결과를 반환한다.

- [ ] 중간 실패로 일부 품목만 반영되지 않도록 하고, 성공 후 두 사람의 채팅 카드와 재고 캐시를 갱신한다.

- [ ] AI의 자체 판단 변경에는 기존 확인·취소와 5분 만료 규칙을 적용한다. 영수증 초안의 유효기간은 별도 정책으로 정한다.

영수증 내용을 확인하는 동안 AI 실행을 계속 점유하지 않는다. 초안 준비가 끝나면 AI 작업을 완료하고, 사용자의 확인은 앱 API가 재고에 반영한다.

## A6 사진 업로드와 삭제

- [ ] 비공개 버킷과 가정별 파일 경로를 만들고 업로드·완료 확인·짧은 URL 발급 API를 구현한다.

- [ ] 업로드 전에 브라우저에서 사진을 압축한다. 사진당 약 1MB 이하는 초기 목표이며 글자 인식 품질을 우선한다.

- [ ] JPEG·PNG·WebP를 먼저 지원하고, 휴대폰의 다른 이미지 형식은 변환 또는 명확한 안내로 처리한다.

- [ ] 만료된 사진으로 새 AI 분석을 시작하지 않고 다시 첨부하도록 안내한다.

- [ ] 제안된 24시간 보관 정책을 채택하면 expires_at을 저장하고 pg_cron이 5분마다 인증된 정리 API를 호출하게 한다.

- [ ] Storage API의 remove로 실제 파일을 삭제한 후에만 deleted_at을 기록한다. 실패한 파일은 다음 정리 주기에 재시도한다.

- [ ] 삭제된 사진은 만료 표시로 바꾸고 품목 초안·재고 반영 결과는 유지한다.

사진 원본 24시간 보관과 5분 주기 정리는 아직 설계 제안이다. 정상 정리 시 물리 삭제는 업로드 후 약 24시간에서 24시간 5분 사이이며, 장애 시 지연될 수 있다. 정리 작업은 맥미니와 독립적으로 실행한다. DB의 Storage 메타데이터만 지우면 실제 파일은 남으므로 Storage API로 삭제한다. [파일 삭제](https://supabase.com/docs/guides/storage/management/delete-objects), [예약 HTTP 호출](https://supabase.com/docs/guides/functions/schedule-functions)

## A7 키와 가족 기억 관리

- [ ] ADR 0016에 따라 Node crypto의 AES-256-GCM으로 AI 키를 암호화한다. SECRET_ENCRYPTION_KEY는 서버 전용 환경 변수에 둔다.

- [ ] 키 버전·IV·인증 태그를 함께 저장하고, 브라우저에는 키 끝자리와 연결 상태만 제공한다.

- [ ] 등록된 맥미니에 해당 가정의 모델 키를 안전하게 공급하는 서버 간 경로를 만든다. 원문 키를 모델 입력·작업 payload·일반 로그에 넣지 않는다.

- [ ] 신뢰된 워커에 대한 키 공급 예외와 키 교체·삭제 때의 실행 중 작업 처리 방식을 ADR에 명시한다.

- [ ] family_memories를 기억의 원본으로 두는 안을 적용하고 목록·수정·삭제·끄기·초기화 API와 화면을 만든다.

- [ ] 기억 변경 버전을 워커에 알리고, 다음 대화가 이전 기억을 계속 사용하지 않도록 한다.

- [ ] 원문 대화의 90일 보존 정책과 가정 삭제 요청을 Supabase와 Hermes 저장소 모두에 적용하도록 정리 작업을 연결한다.

## 앱 코드 배치 제안

채팅 데이터는 src/entities/chat-message, 전송 행동은 src/features/chat-send, 전용 대화 화면은 src/pages/chat에 둔다. 2026-11-04 사용자 요청에 따라 앱 셸의 AI 플로팅 버튼이 `/chat`으로 이동한다. 영수증 확인·반영은 재고 entity를 조합하는 기능으로 배치한다. 루트 app/api의 라우트는 얇게 두고, 여러 entity를 호출하는 도구 조립은 src/app/api에서 수행한다. 클라이언트와 서버 public API를 분리하는 기존 FSD 규칙을 따른다.
